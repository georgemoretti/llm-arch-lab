# Свой токенизатор с merges GPT-2: сверка с эталонным

## Зачем это нужно

В A11–A13 собраны все части byte-level BPE. Осталось проверить их на настоящем токенизаторе. Обученные
слияния GPT-2 лежат в двух текстовых файлах рядом с весами модели: `vocab.json` и `merges.txt`. Если
прочитать их правильно, твой код выдаёт ровно те же id, что библиотека `tokenizers` от Hugging Face, на
любом тексте. Значит, им можно кормить настоящую GPT-2 (C00 и C24 работают с её весами).

Попутно станет видно, почему GPT-2 плохо работает с русским языком. Её словарь обучен на английском
тексте, и у кириллицы почти нет своих слияний.

## Что поменялось относительно A13

| | A13 | A14 |
|---|---|---|
| откуда merges | `train_regex_bpe` на нашем корпусе | `merges.txt` GPT-2, 50 000 правил |
| id токенов | свои: байт = id, слияние k → 256 + k | наружу — id из `vocab.json` |
| спецтокены | задаём сами | берём из `vocab.json` (`<\|endoftext\|>` = 50 256) |
| проверка | эталон курса | библиотека `tokenizers` (`--weights`) |

## Формула

Файлы GPT-2 записаны через отображение $u$ из A13 (пробел = `Ġ`). Строка $k$ файла `merges.txt` (не
считая заголовка `#version: 0.2`) — правило «$a$ $b$», где $a$ и $b$ — строки уже известных токенов:

$$
\text{merges}\big[(\operatorname{id}(a), \operatorname{id}(b))\big] = 256 + k,
\qquad
\operatorname{id}(a \Vert b) = 256 + k,
\qquad
\operatorname{id}(u(\text{байт})) = \text{байт}.
$$

Ранг правила — номер строки: так в GPT-2 упорядочены слияния при обучении. Наши id удобны для BPE, но
модель знает только id из `vocab.json`. Поэтому нужен перевод
$\text{to\_gpt2}[\operatorname{id}(s)] = \text{vocab.json}[s]$ для каждой строки токена $s$. Он не
тождественный: у байта `!` id 0, у пробела `Ġ` — 220. Таких строк ровно $256 + 50\,000 = 50\,256$, и
единственная строка `vocab.json` вне этого набора — спецтокен `<|endoftext|>` с id 50 256. Итого 50 257
токенов (файлы модели [openai-community/gpt2](https://huggingface.co/openai-community/gpt2/tree/main)).

## Формы тензоров

```shapes
## загрузка
- merges.txt: 50 000 строк «a b» после заголовка
> строки → свои id через bytes_to_unicode; k-я строка → 256 + k
merges [K] — {(id a, id b): 256 + k}, K = 50 000
- vocab.json: {строка токена: id GPT-2}
> to_gpt2[свой id] = vocab.json[строка]
to_gpt2 [V] — V = 50 256 (+ спецтокен отдельно)
## encode
- text
> split_special → pretokenize → encode куска (A12)
ours [n] — свои id
> to_gpt2
ids [n] — id GPT-2, их понимает модель
axis K = число слияний
axis V = размер словаря без спецтокенов
```

## Задание

В `solution.py` (рабочая копия в `workspace/A14-gpt2-tokenizer/`):

1. `load_gpt2_files(vocab_path, merges_path)` → `(merges, to_gpt2, special)`. Заголовок и пустые строки
   `merges.txt` пропусти.
2. `GPT2Tokenizer.encode(text, allowed_special=True)` — как `encode_with_special` из A13, но с переводом в
   id GPT-2. При `allowed_special=False` спецтокен в тексте кодируется как обычные символы.
3. `GPT2Tokenizer.decode(ids)` — обратно: id GPT-2 → свои id → байты → один decode UTF-8.

Конструктор готов. Функции A11–A13 (`bytes_to_unicode`, `pretokenize`, `split_special`, `encode`,
`build_vocab`) импортированы из эталонов.

Тесты без сети создают игрушечные `vocab.json` и `merges.txt` в формате GPT-2 из BPE на нашем корпусе, с
перемешанными id. Сверка с настоящим токенизатором запускается флагом `--weights`: нужны
`uv sync --extra weights` и около 2 МБ трафика на три файла.

```bash
llmlab test A14-gpt2-tokenizer             # без сети
llmlab test A14-gpt2-tokenizer --weights   # + настоящие файлы GPT-2 и библиотека tokenizers
```

## Что увидишь на настоящих файлах

На корпусе курса (8 360 символов, 15 189 байтов) GPT-2 тратит **9 048 токенов**, то есть больше одного
токена на символ. Типичное русское слово разбивается почти по байтам: « привет» → `b" \xd0"`, `b"\xbf"`,
`b"\xd1\x80"`, … Английская фраза из 135 символов занимает 28 токенов, а русская того же смысла из 140
символов — 152. Для модели это значит в 5 раз меньше текста в том же контексте и в 5 раз больше шагов
генерации. Токенизатор из A13 с 500 слияниями, обученный на самом корпусе, кодирует его в 3 390 токенов
(сравнение нечестное: он видел этот текст при обучении, но порядок разницы показательный). Поэтому у
многоязычных моделей словари больше: например, у Llama 3 — 128 256 токенов (`vocab_size` в
[config.json Llama 3 8B](https://huggingface.co/meta-llama/Meta-Llama-3-8B/blob/main/config.json)).

## Критерии готовности

- загружено ровно столько правил, сколько строк после заголовка; ранги начинаются с 256 и совпадают с
  порядком строк;
- `to_gpt2` совпадает с id из `vocab.json` (не тождественный), спецтокены найдены;
- `encode` равен ожидаемым id GPT-2 на русском, английском, коде, эмодзи и тексте со спецтокеном;
  `allowed_special=False` не порождает id спецтокена;
- правило, которое склеивает «a» и пробел следующего куска, не применяется через границу кусков;
- `decode(encode(s)) == s`;
- с `--weights`: 50 000 слияний, `<|endoftext|>` = 50 256, «Hello world» → `[15496, 995]`, и полное
  совпадение с `tokenizers` на корпусе, пробелах, переводах строк и эмодзи.

Запуск: `llmlab test A14-gpt2-tokenizer`.
