# C25a. Сэмплирование: temperature, top-k, top-p

## Зачем это нужно

`generate` из C06 всегда берёт самый вероятный токен (argmax). Это детерминированно и хорошо для сверки с
эталоном, но плохо для живого текста: жадная генерация быстро зацикливается («the the the…», повторы фраз), а
на открытых задачах выдаёт самый банальный ответ. Поэтому настоящие модели **сэмплируют**: выбирают
следующий токен случайно, с вероятностями из softmax.

Чистое сэмплирование из всего словаря тоже плохо: у 150 000 токенов длинный хвост маловероятных вариантов, и
хотя каждый из них редок, вместе они выпадают часто — текст «уплывает» в бессмыслицу. Три ручки управляют
этим компромиссом:

- **temperature** $T$ меняет форму распределения: $T < 1$ обостряет (ближе к жадному), $T > 1$ сглаживает;
- **top-k** оставляет $k$ самых вероятных токенов;
- **top-p** (nucleus, Holtzman et al., 2019) оставляет наименьший набор самых вероятных токенов с суммарной
  вероятностью $\ge p$. В отличие от top-k, размер набора подстраивается под уверенность модели: когда она
  уверена, это 1–2 токена, когда нет — десятки.

Эту функцию в C25 использует `generate` на настоящих весах Qwen3-0.6B.

## Что поменялось относительно C06

| | C06 (`generate`) | C25a (`sample_next`) |
|---|---|---|
| выбор токена | $\arg\max z$ | $x \sim \operatorname{softmax}(z / T)$ на отсечённом наборе |
| случайность | нет | `torch.Generator` — тот же сид даёт те же токены |
| параметры | — | `temperature`, `top_k`, `top_p` |
| частный случай | — | $T = 0$ или `top_k = 1` → снова argmax |

## Формула

Логиты $z \in \mathbb{R}^V$, $T > 0$. Отсортируем вероятности $p = \operatorname{softmax}(z / T)$ по убыванию:
$p_{(1)} \ge p_{(2)} \ge \dots$ Токен с рангом $i$ остаётся, если

$$
\underbrace{i \le k}_{\text{top-}k}\quad\text{и}\quad
\underbrace{\sum_{j<i} p_{(j)} < p}_{\text{top-}p},
\qquad
x_{t+1} \sim \operatorname{softmax}\big(z / T\big)\Big|_{\text{оставшиеся}}
$$

Условие top-p смотрит на массу токенов **выше** текущего: токен, который пересекает порог, входит в набор, а
самый вероятный ($\sum_{j<1} = 0$) остаётся всегда. Если сумма ровно равна $p$, набор на этом заканчивается:
следующий токен уже не нужен. Отсечённым токенам ставится $-\infty$, и softmax сам перенормирует вероятности
оставшихся.

## Формы тензоров

```
logits                       [B, V]
  T = 0:  argmax(dim=-1, keepdim=True)                        → [B, 1] long
  z = logits.float() / T     [B, V]
  top-k:  kth = z.topk(min(k, V)).values[:, -1:]   [B, 1];   z[z < kth] = −inf
  top-p:  z_s, order = z.sort(descending=True)     [B, V], [B, V]
          before = cumsum(softmax(z_s)) − softmax(z_s)        [B, V]   масса выше токена
          z_s[before ≥ p] = −inf;  z = scatter(z_s → order)  [B, V]   обратно на места словаря
  multinomial(softmax(z), 1, generator)                       → [B, 1] long
```

## Задание

В `solution.py` (рабочая копия в `workspace/C25a-sampling/`) реализуй
`sample_next(logits, temperature=0.0, top_k=None, top_p=None, generator=None)` → `[B, 1]` (long):

- `temperature == 0` — жадный выбор, `generator` не используется;
- `top_k` и `top_p` можно включать вместе (сначала top-k, потом top-p);
- `generator` передай в `torch.multinomial` — иначе генерацию не воспроизвести.

Готовые `generate` и сэмплирование из `transformers` использовать нельзя: смысл в том, чтобы написать отсечение самому.

## Критерии готовности

- $T = 0$ — argmax, форма `[B, 1]`, тип `long`; `top_k = 1` — argmax при любой температуре;
- частоты на 4000 выборках совпадают с теорией: $T = 0.5$ и $T = 2$, top-k = 2 (перенормировка 0.5 / 0.8),
  top-p = 0.7 и 0.4;
- ядро top-p не зависит от порядка токенов в словаре; при сумме, ровно равной $p$, лишний токен не попадает;
- `top_k` больше словаря ничего не ломает;
- один и тот же `generator` с тем же сидом даёт те же токены.
