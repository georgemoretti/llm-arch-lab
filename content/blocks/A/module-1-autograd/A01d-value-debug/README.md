# Отладка: градиенты верны на простых выражениях и врут на сложных

## Зачем это нужно

Ошибку в autograd трудно заметить: модель всё равно обучается, лосс падает, просто медленнее и
хуже, чем должен. Поэтому градиенты проверяют на маленьких выражениях, где ответ известен. А
когда проверка не сходится, по набору примеров «сходится / не сходится» восстанавливают, что
именно сломано.

## Что поменялось относительно A01

Ничего: это тот же класс `Value`. Код написал кто-то другой, и в нём **одна** ошибка.

## Формула

Правильный chain rule, как в A01:

$$
\frac{\partial L}{\partial v} = \sum_{u \,\in\, \text{потребители}(v)} \frac{\partial L}{\partial u}\,\frac{\partial u}{\partial v},
\qquad \frac{\partial L}{\partial L} = 1.
$$

## Формы тензоров

```shapes
x [] — вход
> операции прямого прохода
L [] — выход
> backward: обратный топологический порядок
x.grad [] — ∂L/∂x
```

Все значения скалярные. Ошибка не в прямом проходе: `data` везде правильные.

## Симптом

Мы сравнили этот `Value` с `torch.autograd`:

- все унарные операции (`exp`, `log`, `tanh`, `relu`, степени) дают верные производные;
- `2 * x`, `x / 4`, нейрон `tanh(w·x + b)` и цепочка из 5000 операций тоже сходятся;
- но `a·b + a` при a = 2, b = −3 даёт ∂/∂a = −3 вместо b + 1 = −2, а `x·x + x` при x = 3 даёт 3 вместо 7;
- на выражениях с общими подвыражениями расхождение с torch в разы.
