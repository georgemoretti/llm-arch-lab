# Головы дообучения: классификация, разметка токенов, extractive QA

## Зачем это нужно

Главная идея BERT — **предобучи один раз, дообучи под что угодно**. К предобученному энкодеру добавляют
крошечную голову и учат всю модель на размеченных данных задачи несколько эпох. В статье BERT так получены лучшие
на тот момент результаты на GLUE, SQuAD и NER — почти без изменений архитектуры (раздел 4 и рисунок 4).

Три типичные головы:

- **классификация текста или пары** (тональность, «следует ли B из A»): линейный слой над pooled-выходом `[CLS]`;
- **разметка токенов** (NER, части речи): линейный слой над каждым токеном. Метки даны для **слов**, а модель
  видит подтокены: `нижний` → `ни ##жний`. Метку ставят на первый подтокен, остальным — `−100`, их не учим;
- **extractive QA** (SQuAD): вход `[CLS] вопрос [SEP] абзац [SEP]`, для каждого токена две оценки — «начало ответа»
  и «конец ответа». Лосс — две cross-entropy по позициям. Ответ — лучшая **пара** (начало, конец): начало не позже
  конца, ответ не длиннее лимита и целиком внутри абзаца.

## Что поменялось относительно B10

| | B10 (предобучение) | B11 (дообучение) |
|---|---|---|
| голова | MLM: логиты по словарю на каждой позиции | классификатор `[H → n]` / по токенам / две оценки на токен |
| вход | текст с `[MASK]` | обычный текст или пара `[CLS] A [SEP] B [SEP]` |
| метки | закрытые токены | класс текста / метки слов / позиции ответа |
| данные | миллиарды слов без разметки | тысячи размеченных примеров |

## Формула

Классификация: $\text{logits} = W_c\, \operatorname{dropout}(\text{pooled}) + b_c$.

QA: $s = h W_s$, $e = h W_e$ (оценки на каждый токен), лосс

$$
\mathcal{L}_{\text{QA}} = \tfrac12\Big(\operatorname{CE}(s, i^*) + \operatorname{CE}(e, j^*)\Big),
\qquad
(\hat\imath, \hat\jmath) = \arg\max_{\substack{i \le j < i + L \\ i, j \in \text{абзац}}} \big(s_i + e_j\big).
$$

Сумма $s_i + e_j$ — это логарифм произведения вероятностей начала и конца (с точностью до константы), поэтому
лучшая пара — максимум суммы, а не пара отдельных максимумов: при ограничениях они расходятся.

## Формы тензоров

```shapes
input_ids [B, T]
> BertModel (B10)
seq [B, T, H]
fork
> pooled = tanh(dense(seq[:, 0])), dropout, classifier
class_logits [B, n_labels]
branch
> classifier по каждому токену
token_logits [B, T, n_tags] — метки на первых подтокенах, −100 на остальных
branch
> Linear H → 2, разбить
start_logits, end_logits [B, T]
> все пары: s_i + e_j, маска (j ≥ i, j − i < L, абзац), argmax
span [B, 2]
join
```

## Задание

В `solution.py` (рабочая копия в `workspace/B11-finetune-heads/`):

1. `SequenceClassifier.forward` — pooled → dropout → classifier (имена как в `BertForSequenceClassification`).
2. `align_labels(word_ids, word_labels)` — метки слов → метки токенов (`word_ids` — как у fast-токенизаторов HF:
   номер слова или `None` у спецтокенов).
3. `qa_loss(start_logits, end_logits, start_positions, end_positions)`.
4. `best_span(start_logits, end_logits, context_mask, max_answer_len)` → `(start [B], end [B])`.

## Критерии готовности

- классификатор совпадает с эталоном и с `transformers.BertForSequenceClassification` на тех же весах, берёт
  pooled-выход и за 60 шагов учится находить токен в тексте;
- метка — на первом подтокене слова, `−100` на продолжениях и спецтокенах;
- `qa_loss` — среднее двух cross-entropy;
- `best_span`: конец не раньше начала, длина ≤ лимита, только абзац; совпадает с перебором всех пар.
