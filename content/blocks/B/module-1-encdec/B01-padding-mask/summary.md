## TL;DR

Энкодер видит весь текст сразу: causal-маски нет, каждый токен смотрит и влево, и вправо. Запретить нужно
только PAD-токены, которыми выравнивают тексты разной длины в батче. Padding-маска запрещает PAD-**ключи**
(столбцы матрицы оценок), а не запросы: тогда выход на настоящих токенах не зависит ни от числа PAD, ни от их
содержимого. Выходы на PAD-позициях считаются, но дальше игнорируются. Multi-head: $C$ режется на $H$ голов по
$D = C/H$ (`view(B, L, H, D).transpose(1, 2)`), головы считаются параллельно и склеиваются обратно.

## Формула

$$\operatorname{softmax}\!\Big(\frac{QK^\top}{\sqrt D} + M\Big)V,\qquad M_{b,t,s} = \begin{cases}0, & \text{ключ } s \text{ в тексте } b \text{ не PAD}\\ -\infty, & \text{PAD}\end{cases}$$

## Формы тензоров

```
ids [B,S] → mask [B,1,1,S]
x [B,T,C] → q [B,H,T,D];  context [B,S,C] → k, v [B,H,S,D]
q@kᵀ/√D [B,H,T,S] → masked_fill(~mask, −inf) → softmax(−1) → @v [B,H,T,D] → [B,T,C] → out_proj
```

## Что поменялось относительно A16

Нет causal-маски: энкодер двунаправленный. Появилась маска паддинга по ключам. Голов несколько, а запросы и
ключи могут идти из разных последовательностей (`T ≠ S`) — это пригодится для cross-attention.
