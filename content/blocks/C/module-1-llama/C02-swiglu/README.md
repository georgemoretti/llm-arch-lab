# C02. SwiGLU FFN (вместо GELU-MLP)

## Зачем это нужно

FFN — вторая половина каждого блока трансформера и ~⅔ его параметров. В GPT-2 это
«расширить в 4 раза → GELU → сжать обратно»: каждый скрытый нейрон сам решает, насколько он
активен, глядя только на свой предактиватор.

**Gated Linear Unit** (GLU) добавляет вторую, параллельную проекцию: одна ветка (*gate*) через
нелинейность решает, **насколько открыт** каждый канал, а другая (*up*) несёт **что именно**
пропустить. Произведение двух проекций делает слой «мультипликативным»: модель может
включать/выключать признаки в зависимости от контекста, а не только масштабировать их.
Шейзер (2020) перебрал варианты нелинейности для гейта и показал, что SwiGLU (гейт через
Swish/SiLU) и GeGLU (через GELU) заметно лучше обычного MLP при том же бюджете параметров.
Llama взяла SwiGLU, и это стало стандартом.

## Что поменялось относительно GPT-2

| | GPT-2 MLP | Llama SwiGLU FFN |
|---|---|---|
| матрицы | `c_fc` (C→4C), `c_proj` (4C→C) | `gate_proj`, `up_proj` (C→F), `down_proj` (F→C) |
| нелинейность | GELU на всём скрытом слое | SiLU только на ветке gate |
| объединение | — | поэлементное произведение gate ⊙ up |
| скрытый размер | 4·d | ≈ 8/3·d (округлённо), чтобы параметров было столько же |
| bias | есть | нет |

**Почему 8/3.** У MLP GPT-2 две матрицы: $2 \cdot d \cdot 4d = 8d^2$ параметров. У SwiGLU три
матрицы $d \times F$: $3dF$. Приравниваем $3dF = 8d^2$ → $F = \tfrac{8}{3}d$. Llama дополнительно
округляет F **вверх** до кратного `multiple_of` (удобно для GPU-ядер), а в Llama 3 перед
округлением есть ещё множитель `ffn_dim_multiplier`:

| модель | d | правило | F (`intermediate_size` в config.json) |
|---|---|---|---|
| Llama 2 7B | 4096 | int(8·4096/3) = 10 922 → вверх до ×256 | **11 008** |
| Llama 3 8B | 4096 | 10 922 × 1.3 = 14 198 → вверх до ×1024 | **14 336** = 3.5·d |

Источники: `intermediate_size` — config.json `meta-llama/Llama-2-7b-hf` и
`meta-llama/Meta-Llama-3-8B` (сверено по открытым зеркалам NousResearch). Значения
`multiple_of = 1024` и `ffn_dim_multiplier = 1.3` для Llama 3 8B взяты из `original/params.json`
оригинального чекпойнта Meta (репозиторий закрыт; сверено по копиям файла в открытых зеркалах, например
`gradientai/Meta-Llama-3-8B-bf16`), и арифметика даёт ровно 14 336 из config.json. Правило — функция `FeedForward.__init__` в `model.py` репозитория
`meta-llama/llama3`.

## Формула

$$
\operatorname{SiLU}(z) = z \cdot \sigma(z) = \frac{z}{1 + e^{-z}}
$$

$$
\operatorname{FFN}(x) = W_{\text{down}}\,\bigl(\operatorname{SiLU}(W_{\text{gate}}\,x) \odot W_{\text{up}}\,x\bigr)
$$

- SiLU гладкая, $\operatorname{SiLU}(0) = 0$, при больших $z$ ведёт себя как $z$, при больших
  отрицательных — как 0, а минимум ≈ −0.278 при $z \approx -1.28$.
- Нелинейность только у gate: по ветке up выход **линеен** (умножь $W_{\text{up}}$ на 3 — выход
  утроится). Если gate «закрыт» ($W_{\text{gate}} = 0$) — выход ровно 0.

## Формы тензоров

```
x                         [B, T, C]
  ├─ gate_proj (C → F)  →  g        [B, T, F] ─ silu ─┐
  └─ up_proj   (C → F)  →  u        [B, T, F] ────────┤
                                                       ⊙  поэлементно
                                    h        [B, T, F] ◄┘
  down_proj (F → C)
  ▼
y                         [B, T, C]
```

FFN действует на каждый токен отдельно — по оси T ничего не смешивается.

## Задание

В `solution.py` (рабочая копия в `workspace/C02-swiglu/`) реализуй:

1. `silu(x)` — без `F.silu` и `nn.SiLU` (тесты это проверяют).
2. `llama_ffn_hidden_dim(d_model, multiple_of=256, ffn_dim_multiplier=None)` — правило из
   таблицы выше: `int(2·4d/3)`, затем (если задан) `int(multiplier · hidden)`, затем округление
   **вверх** до кратного `multiple_of`.
3. `SwiGLUFFN.forward(x)` — конструктор готов, имена параметров как в Llama; не меняй его.

## Критерии готовности

- `silu` совпадает с $z\,\sigma(z)$, SiLU(0) = 0, минимум ≈ −0.278;
- `llama_ffn_hidden_dim` даёт 11 008 для Llama 2 7B, 14 336 для Llama 3 8B и верные значения для
  маленьких размеров;
- FFN сохраняет форму `[B, T, C]` и численно совпадает с эталоном при тех же весах;
- ветка up линейна, закрытый gate даёт 0, нулевой вход — 0 (нет bias);
- токены обрабатываются независимо, градиент доходит до всех трёх матриц.
