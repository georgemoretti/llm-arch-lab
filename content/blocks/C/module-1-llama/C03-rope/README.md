# C03. Rotary Position Embeddings (RoPE)

## Зачем это нужно

Attention сам по себе не знает порядка токенов: если переставить ключи вместе со значениями,
результат для запроса не изменится. GPT-2 решает это **обучаемыми абсолютными эмбеддингами**:
к эмбеддингу токена на входе прибавляется вектор его позиции `wpe[t]`. У такого подхода три
слабости:

- модель знает только позиции, которые видела при обучении (у GPT-2 — 1024), дальше таблицы нет;
- для языка важнее **относительное** расстояние («слово два токена назад»), а абсолютная позиция
  смешана с содержанием токена ещё до первого слоя, и вытаскивать расстояние модели приходится
  самой;
- позиционный сигнал добавляется один раз и «размывается» по мере прохождения слоёв.

**RoPE** (Su et al., 2021) кодирует позицию прямо в attention каждого слоя, и так, чтобы
оценка $q_m \cdot k_n$ зависела только от разности $m - n$. Идея: разбить вектор головы на пары
координат и **повернуть** каждую пару на угол, пропорциональный позиции. Поворот сохраняет длину
вектора, а скалярное произведение двух повёрнутых векторов зависит только от разности углов.

## Что поменялось относительно GPT-2

| | GPT-2 | Llama (RoPE) |
|---|---|---|
| где позиция | `wte[tok] + wpe[t]` на входе модели | поворот q и k внутри **каждого** слоя attention |
| параметры | таблица `wpe` [1024, C] | нет — только фиксированные частоты |
| что кодируется | абсолютная позиция | в score — относительная (m − n) |
| v | — | не поворачивается |
| максимальная длина | жёстко 1024 | ограничена обучением, но таблицы нет; θ задаёт «масштаб» |

В Llama 3 8B `rope_theta = 500 000` (config.json; у Llama 2 было 10 000), `rope_scaling = null`,
обучающий контекст 8192 (`max_position_embeddings`). Источник: config.json
`meta-llama/Meta-Llama-3-8B`, сверено по открытому зеркалу `NousResearch/Meta-Llama-3-8B`.

## Формула

Вектор головы $x \in \mathbb{R}^D$ делим на $D/2$ пар. Частота пары $i$:

$$
\theta_i = \theta^{-2i/D}, \qquad i = 0, \dots, \tfrac{D}{2} - 1
$$

Пара 0 вращается быстрее всех (частота 1 рад на позицию), последняя — медленнее всех (≈ 1/θ).
На позиции $m$ пара $(a, b)$ поворачивается на угол $m\theta_i$:

$$
\begin{pmatrix} a' \\ b' \end{pmatrix} =
\begin{pmatrix} \cos m\theta_i & -\sin m\theta_i \\ \sin m\theta_i & \cos m\theta_i \end{pmatrix}
\begin{pmatrix} a \\ b \end{pmatrix}
$$

Обозначим поворот всего вектора $R_m$. Он ортогонален, и $R_m^\top R_n = R_{n-m}$, поэтому

$$
\langle R_m q,\; R_n k \rangle = q^\top R_m^\top R_n k = \langle q,\; R_{n-m}\, k\rangle
$$

— абсолютные позиции сокращаются, остаётся только разность.

**Какие координаты образуют пару.** Есть две раскладки:

- *интерливная* (статья RoFormer, оригинальный код Meta): пары $(x_0, x_1), (x_2, x_3), \dots$;
- *половинами* (Hugging Face `transformers`, GPT-NeoX): пары $(x_j, x_{j + D/2})$.

Математически это одно и то же с точностью до перестановки координат; при конвертации весов
Meta в формат HF строки проекций $W_Q, W_K$ переставляют, чтобы код «половинами» давал те же
числа. В этой задаче — раскладка **половинами**. Для неё поворот всех пар сразу записывается
коротко:

$$
\operatorname{RoPE}(x, m) = x \odot \cos(m\boldsymbol\theta) + \operatorname{rotate\_half}(x) \odot \sin(m\boldsymbol\theta),
\qquad \operatorname{rotate\_half}([x_1 \,|\, x_2]) = [-x_2 \,|\, x_1]
$$

где вектор углов $m\boldsymbol\theta = [m\theta_0, \dots, m\theta_{D/2-1},\; m\theta_0, \dots, m\theta_{D/2-1}]$
— углы повторены дважды, по одному разу для каждой половины. Проверь на паре $(a, b) = (x_j, x_{j+D/2})$:
первая половина даёт $a\cos - b\sin$, вторая $b\cos + a\sin$ — ровно поворот.

## Формы тензоров

```
positions          [T]          (номера позиций; при KV-cache — не обязательно с нуля)
inv_freq           [D/2]        θ^(−2i/D)
  │ positions[:, None] * inv_freq[None, :]
  ▼
angles             [T, D/2]
  │ cat((angles, angles), dim=-1)      — одна частота на пару (j, j + D/2)
  ▼
cos, sin           [T, D]       каждый

q (или k)          [B, H, T, D]
  │ q * cos + rotate_half(q) * sin     — cos/sin транслируются по B и H
  ▼
q_rot              [B, H, T, D]
```

В attention-слое RoPE применяется после разбиения на головы и до $QK^\top$ — к q и к k, но не к v.
Встраивание в слой — в C06; здесь только сами функции.

## Задание

В `solution.py` (рабочая копия в `workspace/C03-rope/`) реализуй:

1. `rope_inv_freq(head_dim, theta)` → `[D/2]`;
2. `rope_cos_sin(positions, head_dim, theta)` → `(cos, sin)`, каждый `[T, D]`; `positions` —
   тензор номеров позиций, не обязательно `arange(T)`;
3. `rotate_half(x)` — по последней оси, при любом числе ведущих осей;
4. `apply_rope(x, cos, sin)` для `x [B, H, T, D]`.

Готовых реализаций RoPE в PyTorch нет, так что ограничений нет — но и циклов не нужно.

## Критерии готовности

- частоты $\theta^{-2i/D}$: их $D/2$, первая равна 1;
- `cos`/`sin` формы `[T, D]`, на позиции 0 — 1 и 0, половины одинаковые, углы верны для
  произвольных позиций;
- `rotate_half([1..6]) = [−4, −5, −6, 1, 2, 3]`;
- на позиции 0 вектор не меняется; при D = 2 это поворот на m радиан; норма сохраняется;
  результат совпадает с независимым оракулом через комплексные числа;
- score $\langle q_m, k_n\rangle$ зависит только от $m - n$;
- работает с θ = 500 000 и смещёнными позициями; θ действительно влияет на результат.
