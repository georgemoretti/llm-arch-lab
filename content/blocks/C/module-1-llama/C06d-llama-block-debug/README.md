# Отладка: блок Llama не пропускает сигнал, даже когда подслои молчат

## Зачем это нужно

Ошибки сборки блока не роняют код: формы правильные, модель генерирует, с кешем и без кеша
токены одинаковые. Но веса, обученные для одной схемы, в другой дают мусор, а при обучении с
нуля такая модель хуже учится в глубину. Задача — найти ошибку по **свойству** правильного
блока, а не сравнением чисел.

## Что поменялось относительно C06

Архитектура та же — `LlamaBlock` и `LlamaModel` из C06. Код написан кем-то другим, и в нём
**одна** ошибка.

## Формула

$$
h = x + \operatorname{Attn}\big(\operatorname{RMSNorm}_1(x)\big), \qquad
y = h + \operatorname{SwiGLU}\big(\operatorname{RMSNorm}_2(h)\big)
$$

## Формы тензоров

```shapes
idx [B, T]
> embed_tokens
x [B, T, C]
> L × LlamaBlock
x [B, T, C]
> norm → lm_head
logits [B, T, V]
```

Все формы и имена параметров в коде правильные.

## Симптом

- веса эталона загружаются без ошибок, формы логитов верные;
- будущее не протекает; генерация с кешем и без кеша даёт одинаковые токены;
- но логиты не совпадают с эталоном, а если обнулить `o_proj` и `down_proj` (подслои выдают
  ноль), блок всё равно **меняет** вход — хотя должен вернуть его как есть.

Код — в `workspace/C06d-llama-block-debug/solution.py`. Найди и исправь ошибку.
