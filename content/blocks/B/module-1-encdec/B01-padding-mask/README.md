# Padding-маска и двунаправленное multi-head attention

## Зачем это нужно

Блок A закончился декодером: каждый токен смотрит только в прошлое, потому что модель учится угадывать
следующий. Исходный Transformer (Vaswani et al., 2017) решал другую задачу — перевод. Ему нужно сначала
**прочитать** предложение целиком и только потом писать перевод. Читает **энкодер**. Ему незачем прятать
будущее: исходный текст известен полностью, и смысл слова часто проясняется только справа («ключ от
двери» и «ключ к задаче»). Поэтому causal-маски в энкодере нет: каждый токен видит весь текст.

Зато появляется другая проблема. Тексты в батче разной длины, а тензор должен быть прямоугольным. Короткие
тексты дополняют служебным токеном **PAD**. Он не несёт смысла, и настоящие токены не должны его учитывать:
иначе ответ модели зависел бы от того, с какими соседями по батчу пришёл текст. Это запрещает
**padding-маска**.

Вторая новинка — **multi-head**. В A16 была одна голова. Здесь вектор размера $C$ режется на $H$ голов по
$D = C/H$. Каждая голова считает своё attention в своём подпространстве: одна может следить за соседним
словом, другая — за подлежащим. Стоимость та же, что у одной большой головы.

## Что поменялось относительно A16

| | A16 (декодер, одна голова) | B01 (энкодер, multi-head) |
|---|---|---|
| маска | causal $[T, T]$: только прошлое | padding $[B, 1, 1, S]$: все, кроме PAD |
| голов | одна размера $D$ | $H$ голов по $D = C/H$, затем `out_proj` |
| откуда K и V | из того же $x$ | из `context` (по умолчанию $x$); пригодится для cross-attention в B04 |
| форма оценок | $[B, T, T]$ | $[B, H, T, S]$, $T$ может не равняться $S$ |

## Формула

$$
\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\Big(\frac{Q K^{\top}}{\sqrt{D}} + M\Big) V,
\qquad
M_{b,s} =
\begin{cases} 0, & \text{токен } s \text{ текста } b \text{ настоящий},\\ -\infty, & \text{PAD}. \end{cases}
$$

Маска зависит только от **ключа** $s$. Она запрещает столбцы матрицы оценок, а не строки. Строки PAD-запросов
считаются как обычно: каждая видит настоящие токены, $\text{nan}$ не появляется, а их выход потом просто
игнорируют (в лоссе, в пулинге). Если бы маска запрещала строки, у PAD-запроса все оценки стали бы
$-\infty$, softmax дал бы $0/0 = \text{nan}$, а настоящие токены продолжали бы смотреть на PAD.

Multi-head:

$$
\operatorname{MHA}(x, c) = \operatorname{Concat}(\text{head}_1, \dots, \text{head}_H)\, W_O,
\qquad
\text{head}_h = \operatorname{Attention}(x W_Q^{(h)},\; c W_K^{(h)},\; c W_V^{(h)}).
$$

Все $W_Q^{(h)}$ хранятся одной матрицей `q_proj` размера $C \times C$. Голова $h$ — это столбцы
$hD \dots (h+1)D - 1$ её выхода.

## Формы тензоров

```shapes
x [B, T, C] — запросы
fork
> q_proj, разрезать на головы
q [B, H, T, D]
branch
context [B, S, C] — ключи и значения (= x в self-attention)
> k_proj, v_proj, разрезать на головы
k, v [B, H, S, D]
join
> q @ kᵀ / √D
scores [B, H, T, S]
> masked_fill(~mask, −inf); mask [B, 1, 1, S] растягивается по H и T
> softmax по ключам (dim = −1)
weights [B, H, T, S]
> weights @ v
out [B, H, T, D]
> transpose(1, 2), reshape
out [B, T, C]
> out_proj
y [B, T, C]
axis H = n_heads
axis D = C / H
axis S = длина context
```

«Разрезать на головы» — это `view(B, L, H, D).transpose(1, 2)`. Порядок важен: вектор **каждой позиции**
делится на $H$ кусков. `view(B, H, L, D)` даст ту же форму, но в одну голову попадут куски разных позиций.

## Задание

В `solution.py` (рабочая копия в `workspace/B01-padding-mask/`):

1. `padding_mask(ids, pad_id)` → bool `[B, 1, 1, S]`, `True` у настоящих токенов.
2. `attention(q, k, v, mask=None)` → `(out, weights)` для `q [B, H, T, D]`, `k, v [B, H, S, ·]`. Маска любой
   формы, которая растягивается до `[B, H, T, S]`.
3. `MultiHeadAttention.split_heads(x)` и `MultiHeadAttention.forward(x, context=None, mask=None,
   need_weights=False)`.

В курсе `True` в маске значит «можно смотреть». В PyTorch у `key_padding_mask` в `nn.MultiheadAttention`
смысл обратный: `True` = игнорировать. Это частый источник ошибок при переносе кода.

`F.scaled_dot_product_attention` и `nn.MultiheadAttention` запрещены: тесты используют их как эталон.

## Критерии готовности

- маска — bool `[B, 1, 1, S]`, `True` у настоящих токенов;
- `attention` совпадает с `F.scaled_dot_product_attention` без маски, с padding-маской и с маской
  `[B, 1, T, S]`; веса PAD-ключей ровно 0, строки суммируются в 1, работает при `T ≠ S`;
- `MultiHeadAttention` совпадает с `nn.MultiheadAttention` с теми же весами (self и cross);
- выход на настоящих токенах не зависит от числа PAD и от их содержимого, `nan` нет;
- позиция 0 видит последний токен; перестановка входа переставляет выход.
