# Пре-токенизация GPT-2, спецтокены и byte ↔ unicode

## Зачем это нужно

Токенизатор из A11–A12 видит текст как одну длинную ленту байтов. Из-за этого слияния смешивают всё
подряд: «слово + пробел + начало следующего слова», «точка + пробел», «буква + запятая». Словарь тратится
на случайные сочетания соседей, и одно и то же слово получает разные токены в зависимости от того, что
стоит после него.

Настоящие токенизаторы перед BPE режут текст на **куски** регулярным выражением: слова, числа,
пунктуация, пробелы. Слияния происходят только внутри куска. Это и есть **пре-токенизация**. Кроме неё
токенизатору LLM нужны ещё две вещи:

- **спецтокены**: `<|endoftext|>` между документами в обучающих данных, служебные токены чата. Они
  кодируются одним id и никогда не собираются из кусков обычного текста;
- **запись токенов строкой**. Файлы GPT-2 (`vocab.json`, `merges.txt`) — текстовые, а токены — байты,
  среди которых есть пробел, перевод строки и половинки символов UTF-8. Поэтому каждый байт отображается в
  печатный символ Unicode. Отсюда в словаре GPT-2 странные токены вроде `Ġworld`: `Ġ` — это пробел.

## Что поменялось относительно A12

| | A12 | A13 |
|---|---|---|
| единица для BPE | весь текст | куски `pretokenize(text)` |
| слияния через пробел и пунктуацию | бывают | невозможны |
| служебные токены | нет | `<\|endoftext\|>` и др. — один id |
| запись токена | `bytes` | ещё и строка из 256 печатных символов (`Ġ` = пробел) |

## Формула

Регулярка GPT-2 — альтернативы, которые пробуются по порядку (первая подходящая забирает кусок):

| № | альтернатива | что забирает | пример |
|---|---|---|---|
| 1 | `'s` `'t` `'re` `'ve` `'m` `'ll` `'d` | английские сокращения | `it's` → `it`, `'s` |
| 2 | ` ?\p{L}+` | необязательный пробел + буквы | ` world`, ` мир` |
| 3 | ` ?\p{N}+` | необязательный пробел + цифры | ` 2024` |
| 4 | ` ?[^\s\p{L}\p{N}]+` | необязательный пробел + прочие символы | `,`, ` =`, `!` |
| 5 | `\s+(?!\S)` | пробелы, после которых нет непробельного символа | `   ` в конце строки |
| 6 | `\s+` | остальные пробелы | `\n` |

Пробел прилипает к **началу** следующего слова: слово в середине предложения всегда выглядит одинаково,
« world». Альтернатива 5 оставляет последний пробел перед словом, поэтому `a  b` режется как
`a`, ` `, ` b`, а не `a`, `  b`. `\p{L}` и `\p{N}` — классы Unicode «буква» и «цифра», их понимает модуль
`regex` (стандартный `re` — нет). Сокращения в GPT-2 чувствительны к регистру: `I'M` режется как
`I`, `'`, `M`.

Отображение байтов в символы. Пусть $\mathcal{V}$ — 188 «видимых» байтов: диапазоны `!`..`~` (33–126),
`¡`..`¬` (161–172) и `®`..`ÿ` (174–255). Тогда

$$
u(b) =
\begin{cases}
\operatorname{chr}(b), & b \in \mathcal{V},\\
\operatorname{chr}(256 + j), & b \notin \mathcal{V},\ b \text{ — } j\text{-й по счёту из остальных 68 байтов (с нуля)}.
\end{cases}
$$

Пробел (байт 32) — 33-й невидимый байт (после 0..31), поэтому $u(32) = \operatorname{chr}(288) =$ `Ġ`,
а перевод строки $u(10) = \operatorname{chr}(266) =$ `Ċ`.

Как это выглядит в GPT-2 (по файлам `vocab.json` и `merges.txt` модели
[openai-community/gpt2](https://huggingface.co/openai-community/gpt2)): словарь — 50 257 токенов, это
256 байтов, 50 000 слияний и один спецтокен `<|endoftext|>` с id 50 256. У более новых моделей та же
схема с другой регуляркой. Например, у Llama 3 цифры режутся группами не длиннее трёх (`\p{N}{1,3}`), а
сокращения не зависят от регистра (см. `tokenizer.py` в репозитории
[meta-llama/llama3](https://github.com/meta-llama/llama3/blob/main/llama/tokenizer.py)).

## Формы тензоров

```shapes
- text: «Привет, мир<|endoftext|>Hi»
> split_special
parts [p] — ["Привет, мир", "<|endoftext|>", "Hi"]
> спецтокен → его id; обычный текст → pretokenize
chunks [c] — ["Привет", ",", " мир"], ["Hi"]
> encode каждого куска отдельно (A12)
ids [n] — id кусков + id спецтокена, по порядку
## decode
ids [n]
> байты: vocab[id] или строка спецтокена в UTF-8
- b"".join → .decode("utf-8", errors="replace")
axis p = части текста между спецтокенами
axis c = куски после пре-токенизации
```

## Задание

В `solution.py` (рабочая копия в `workspace/A13-pretokenize/`):

1. `GPT2_PATTERN` и `pretokenize(text)` — регулярка из таблицы и `regex.findall`.
2. `bytes_to_unicode()` → `{байт: символ}` по формуле выше.
3. `train_regex_bpe(text, vocab_size)` — `train_bpe` (импортирован из эталона A11) по кускам
   `pretokenize`.
4. `split_special(text, special)` — части текста и спецтокены по порядку, без пустых строк.
5. `encode_with_special(text, merges, special)` и `decode_with_special(ids, vocab, special)`. `encode`
   из A12 уже импортирован.

## Критерии готовности

- `pretokenize` даёт куски GPT-2 на 9 примерах (пробел в начале слова, цифры отдельно от букв и от
  пунктуации, хвостовые пробелы, переводы строк), куски склеиваются в исходный текст, корпус режется как
  у эталона;
- `bytes_to_unicode`: 256 разных печатных непробельных символов, видимые байты — сами собой, `Ġ` =
  пробел, `Ċ` = перевод строки, «` мир`» записывается как `ĠÐ¼Ð¸ÑĢ`;
- `train_regex_bpe` совпадает с эталоном, и ни один токен не содержит пробел в середине;
- `split_special` экранирует `|`, сохраняет спецтокены, не возвращает пустых строк;
- спецтокен кодируется одним id, обычный текст — по кускам (даже если в `merges` есть пара через
  границу кусков); без словаря спецтокенов `<|endoftext|>` — обычный текст;
- `decode(encode(s)) == s` с эмодзи, иероглифами и спецтокенами между документами.
