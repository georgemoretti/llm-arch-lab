# BPE: encode по рангам и decode через байты

## Зачем это нужно

В A11 токенизатор выучил список слияний. Теперь им нужно пользоваться: превращать **любой** текст в
id (encode) и обратно (decode). Модель видит только id, поэтому от токенизатора требуются две гарантии.

1. **Детерминизм.** Один и тот же кусок текста всегда кодируется одинаково, как и при обучении. Иначе
   эмбеддинг токена « кот» в одном предложении и разбиение « к» + «от» в другом — это для модели разные
   слова.
2. **Обратимость.** `decode(encode(s)) == s` для любой строки UTF-8: русский текст, эмодзи, иероглифы,
   управляющие символы. Byte-level BPE даёт это бесплатно, но только если decode работает с байтами, а не
   с отдельными токенами.

## Что поменялось относительно A11

| | A11 (обучение) | A12 (кодирование) |
|---|---|---|
| вход | обучающий текст | любой текст |
| какую пару сливать | самую **частую** в тексте | самую **раннюю** по рангу (наименьший id) |
| результат | `merges`, `vocab` | список id / строка |

Главная ловушка — вторая строка таблицы. При кодировании нового текста частоты пар в нём не важны:
токенизатор повторяет порядок, в котором слияния выучены. Именно так кодирование обучающего текста
даёт ровно ту последовательность, что получилась при обучении.

## Формула

Пусть $r(a, b)$ — ранг пары (id токена из `merges`), и $r = \infty$ для пар, которых нет в `merges`.
Один шаг encode:

$$
(a, b)^{*} = \arg\min_{(x_i, x_{i+1})}\ r(x_i, x_{i+1}),
\qquad
x \leftarrow \operatorname{merge}\big(x, (a, b)^{*}, r(a, b)^{*}\big),
$$

и так до тех пор, пока $\min r = \infty$. Decode — склейка байтов и одно декодирование:

$$
\operatorname{decode}(t_1, \dots, t_n) = \operatorname{utf8}^{-1}\big(\text{vocab}[t_1]\,\Vert\,\dots\,\Vert\,\text{vocab}[t_n]\big).
$$

Склеивать нужно **до** декодирования: на русском корпусе первый выученный токен — `b" \xd0"`, пробел и
половина буквы. Отдельно такой токен в строку не превращается.

## Формы тензоров

```shapes
## encode
- text: строка
> text.encode("utf-8")
ids [n] — байты 0..255
> пара с наименьшим рангом → merge_pair
ids [n′] — n′ < n, повторять, пока есть пары из merges
## decode
ids [n′]
> vocab[id]: байты каждого токена
parts [n′] — список bytes
> b"".join → .decode("utf-8", errors="replace")
- text: строка
axis n = число байтов
```

## Задание

В `solution.py` (рабочая копия в `workspace/A12-bpe-encode/`):

1. `encode(text, merges)` → `list[int]`: байты, затем слияния по рангу, пока есть что сливать.
   `merge_pair` уже импортирован из эталона A11.
2. `decode(ids, vocab)` → `str`: склейка байтов и одно декодирование с `errors="replace"`. Модель может
   сгенерировать обрывок символа, и decode не должен на нём падать.

Наивный encode пересчитывает пары после каждого слияния. На длинных текстах это медленно, поэтому
настоящие токенизаторы режут текст на слова (A13) и кешируют их разбиение. Нам хватит простой версии.

## Критерии готовности

- `decode` склеивает байты: «пробел + половина буквы» и вторая половина дают « о», без «�»;
- обрывок символа не роняет `decode`, а превращается в «�»;
- слияния применяются по рангу: при `merges` «ab» → 256, «bc» → 257 строка «bcbcabc» кодируется как
  `[bc, bc, ab, c]`;
- `encode` обучающего текста повторяет последовательность из обучения токен в токен;
- `decode(encode(s)) == s` для корпуса, эмодзи, иероглифов, служебных символов и случайного Unicode;
- на новом русском тексте токенов больше чем вдвое меньше, чем байтов.
