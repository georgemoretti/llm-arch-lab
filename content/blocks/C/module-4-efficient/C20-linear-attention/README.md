# Линейное внимание: kernel trick, параллельная и рекуррентная формы

## Зачем это нужно

У softmax-attention два дорогих места: при обучении — матрица весов $[T, T]$ ($O(T^2)$ времени), при
генерации — KV-cache, растущий линейно с длиной (C05). Sliding window (C07) и DSA (C18) урезают набор ключей,
но сам механизм остаётся прежним.

Линейное внимание (Katharopoulos et al., ICML 2020) меняет механизм. В softmax-attention вес пары — это
$\exp(q^\top k)$. Если заменить его на скалярное произведение признаков $\varphi(q)^\top \varphi(k)$
с положительной $\varphi$, можно переставить скобки:

$$
\Big(\varphi(Q)\,\varphi(K)^\top\Big) V \;=\; \varphi(Q)\,\Big(\varphi(K)^\top V\Big)
$$

Справа нет матрицы $[T, T]$: сначала сжимаем все ключи и значения в матрицу $[d, d_v]$, потом умножаем
на запросы — $O(T)$ вместо $O(T^2)$. Для causal-случая сумма по прошлым токенам накапливается шаг за
шагом, и attention превращается в **RNN** с состоянием фиксированного размера:
$S_t = S_{t-1} + \varphi(k_t) v_t^\top$. Ни KV-cache, ни роста памяти с длиной.

Цена — качество: состояние $[d, d_v]$ — это сжатая сумма всей истории, «память» конечна, и точные
выборки из далёкого прошлого (поиск иголки в стоге) даются плохо. Поэтому современные гибридные модели
берут улучшенные варианты линейного внимания (у Qwen3-Next — Gated DeltaNet, C21) и **смешивают** их с
обычным attention (C22).

## Что поменялось относительно C00

| | C00 (causal softmax MHA) | C20 (линейное внимание) |
|---|---|---|
| вес пары $(t, s)$ | $\exp(q_t^\top k_s / \sqrt d)$ | $\varphi(q_t)^\top \varphi(k_s)$, $\varphi(x) = \operatorname{elu}(x) + 1$ |
| нормировка | softmax | деление на $\sum_{s \le t} \varphi(q_t)^\top \varphi(k_s)$ |
| causal-маска | $-\infty$ до softmax | $0$ у весов (весов-экспонент больше нет) |
| обучение | $O(T^2 d)$ | параллельная форма $O(T^2 d)$ или (чанками, C21) почти $O(T d^2)$ |
| генерация | KV-cache $O(T)$ на слой | состояние $S \in \mathbb{R}^{d \times d_v}$, $z \in \mathbb{R}^{d}$ — $O(1)$ по $T$ |

## Формула

Некаузальная (каждый запрос видит все ключи):

$$
o_t = \frac{\varphi(q_t)^\top \sum_{s} \varphi(k_s) v_s^\top}{\varphi(q_t)^\top \sum_{s} \varphi(k_s)}
$$

Causal, **параллельная** форма (как attention, но без softmax):

$$
A_{ts} = \varphi(q_t)^\top \varphi(k_s)\,[s \le t],\qquad
o_t = \frac{\sum_s A_{ts}\, v_s}{\sum_s A_{ts}}
$$

Causal, **рекуррентная** форма (то же самое, по шагам):

$$
S_t = S_{t-1} + \varphi(k_t)\, v_t^\top,\quad
z_t = z_{t-1} + \varphi(k_t),\qquad
o_t = \frac{\varphi(q_t)^\top S_t}{\varphi(q_t)^\top z_t}
$$

Знаменатель — это сумма тех же весов, что в числителе, поэтому $o_t$ — взвешенное **среднее** значений
$v_s$, $s \le t$. Масштаба $1/\sqrt d$ нет: при делении на сумму весов он сократился бы.

## Формы тензоров

```shapes
q, k [B, H, T, d]
> φ — признаковое отображение
φ(q), φ(k) [B, H, T, d] — все значения > 0
v [B, H, T, dv]

## без маски (noncausal)
φ(K)ᵀV [B, H, d, dv] — считаем первым!
Σ_s φ(k_s) [B, H, d]
> φ(Q)·(φ(K)ᵀV) и φ(Q)·Σφ(k)
числитель [B, H, T, dv]
знаменатель [B, H, T, 1]
> деление
out [B, H, T, dv]

## causal, параллельная форма
A [B, H, T, T] — (φ(Q)φ(K)ᵀ).tril()
> A·V / A.sum(-1, keepdim)
out [B, H, T, dv]

## causal, рекуррентная форма (шаг t)
S [B, H, d, dv] — S += φ(k_t) ⊗ v_t
z [B, H, d] — z += φ(k_t)
> o_t = φ(q_t)ᵀS / φ(q_t)ᵀz
o_t [B, H, dv]
> stack по t
out [B, H, T, dv]
axis d = размер признаков φ(q), φ(k)
axis dv = размер значения
```

## Критерии готовности

- $\varphi > 0$ и равна $\operatorname{elu}(x) + 1$;
- некаузальная форма через $\varphi(K)^\top V$ совпадает с явной формулой;
- causal-форма совпадает с формулой, при постоянных $v$ выдаёт ту же константу (веса суммируются в 1),
  не зависит от будущих токенов;
- рекуррентная форма совпадает с параллельной, $S = \varphi(K)^\top V$, $z = \sum \varphi(k)$; кусками с
  переносом состояния — как целиком;
- размер состояния один и тот же после 2 и после 24 токенов.
