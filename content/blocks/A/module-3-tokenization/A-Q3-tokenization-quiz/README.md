# Квиз модуля: Токенизация

## Зачем это нужно

Токенизатор — часть модели, которую видно хуже всего, но от неё зависят длина контекста, цена генерации,
качество на разных языках и арифметика. На собеседованиях спрашивают, как работает BPE, чем отличаются
алгоритмы токенизации и почему у LLM бывают странности на числах и редких словах. Квиз собирает вопросы
модуля и вопросы с твоих собеседований о токенизации.

## Что ты построил в модуле — в одной таблице

| идея | где | что запомнить |
|---|---|---|
| byte-level BPE | A11 | старт с 256 байтов, $K$ раз слить самую частую пару; UNK не бывает |
| ранг слияния | A11, A12 | id нового токена = 256 + номер слияния |
| encode по рангу | A12, A12d | сливать самую раннюю пару, а не самую частую в тексте |
| decode через байты | A12, A13d | склеить байты всех токенов, один decode UTF-8 с `errors="replace"` |
| пре-токенизация | A13 | регулярка GPT-2: « слово», числа, пунктуация, пробелы; BPE внутри куска |
| спецтокены | A13, A14 | вырезаются до BPE, один id; для текста пользователя — выключены |
| byte ↔ unicode | A13, A14 | 256 байтов → печатные символы, пробел = `Ġ` |
| GPT-2 | A14 | 256 + 50 000 слияний + `<\|endoftext\|>` = 50 257; русский — больше токена на символ |

## Как проходить

1. Открой вкладку **«Вопросы»**.
2. В вопросах с вариантами выбери ответ: сразу будет видно, верен ли он, и объяснение.
3. На открытые вопросы сначала ответь сам (2–4 предложения), затем открой эталон и честно оцени ответ.
4. Если ответил неуверенно, вернись к задаче из таблицы. Её конспект лежит во вкладке «Конспекты».

Оценки попадают в интервальное повторение (SM-2) во вкладке **Interview**.
