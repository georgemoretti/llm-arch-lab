# Проект: мини-поиск по корпусу курса — bi-encoder на ModernBERT против TF-IDF

## Зачем это нужно

Соберём всё из модуля в одну систему: поиск по тексту самого курса. Документы — 736 абзацев из README всех задач.
Запросы для проверки — 298 вопросов курса (те, что во вкладке «Вопросы»). Вопрос считается найденным, если в выдаче
есть абзац README его задачи. Вопросы писали отдельно от README, другими словами, так что это честная проверка «по
смыслу», а не по совпадению фраз.

Размеченных пар «вопрос → абзац» для обучения у нас нет, как и почти всегда в реальном поиске. Поэтому bi-encoder
обучается **без разметки**, на задаче inverse cloze (ICT, Lee et al., 2019): из абзаца вырезается кусок в 6–14 слов, и
модель учится находить по этому куску остаток абзаца среди других абзацев батча (InfoNCE из B19). Энкодер — маленький
ModernBERT из B16 (2 слоя, 96, 0.5 М параметров). Соперник — мешок слов TF-IDF, без всякого обучения.

## Что поменялось относительно B19

| | B19 | B20 |
|---|---|---|
| данные | синтетические «синонимы» | настоящий корпус курса, 210 тыс. символов |
| энкодер | `EmbeddingBag` | ModernBERT (B16) + mean pooling (B18) |
| пары для обучения | даны | строим сами: ICT, кусок ↔ абзац без куска |
| оценка | recall@1 на обучающих парах | отложенные вопросы курса, recall@1 / 5 / 10, и сравнение с TF-IDF |

**Токенизатор.** В корпусе русский текст, а у нас нет обученного токенизатора. Берём грубую морфологию: слово →
«основа» из первых 5 букв + «##окончание» (`маскирование` → `маски ##рование`). Так «маска», «маски» и «маской»
делят основу. Тот же разбор помогает и TF-IDF: по основам он лучше, чем по словам.

## Формула

TF-IDF документа $d$ по термину $t$ (сглаживание как в scikit-learn), затем L2:

$$
\operatorname{idf}(t) = \log\frac{1 + N}{1 + \operatorname{df}(t)} + 1, \qquad
v_{d,t} = \operatorname{tf}(t, d)\cdot \operatorname{idf}(t), \qquad \hat v_d = v_d / \lVert v_d \rVert .
$$

Bi-encoder: $e = \operatorname{L2}(\operatorname{mean}(\operatorname{ModernBERT}(x)))$, лосс — InfoNCE (B19), τ = 0.05, батч
64. Гибрид — взвешенная сумма косинусов: $s = \alpha\, \cos_{\text{bi}} + (1 - \alpha) \cos_{\text{tfidf}}$.

$$\text{hit@}k = \frac{1}{|Q|}\sum_{q} \big[\, \text{top}_k(q) \cap \text{gold}(q) \ne \varnothing \,\big] .$$

## Формы тензоров

```shapes
## обучение
> ICT: кусок 6–14 слов и абзац без куска
q_ids [B, Tq]
d_ids [B, Td]
> ModernBERT (2 слоя) → mean pooling → L2
q [B, C]
d [B, C]
> q·dᵀ / τ → InfoNCE
loss []
## поиск
> все абзацы → эмбеддинги один раз
D [N, C]
> вопрос → эмбеддинг → косинусы
scores [Q, N]
axis B = батч (64)
axis C = hidden (96)
axis N = абзацы (736)
```

## Задание

В `solution.py` (рабочая копия в `workspace/B20-mini-search/`) напиши пять функций из раздела «твоя часть»:

1. `ict_pair(words, rng)` — пара «кусок ↔ контекст»; кусок вырезается из контекста с вероятностью 0.9.
2. `idf_weights(docs, vocab)` и `tfidf_vectors(texts, vocab, idf)` — мешок слов.
3. `train_step(model, opt, q_ids, q_mask, d_ids, d_mask)` — InfoNCE из B19, один шаг.
4. `hit_at_k(scores, gold, k)` — у вопроса несколько правильных абзацев (все абзацы README его задачи).

Корпус, токенизатор, модель, цикл обучения и сравнение готовы. Когда тесты пройдут, запусти обучение:

```bash
python workspace/B20-mini-search/solution.py               # ~1.5 мин на CPU
python workspace/B20-mini-search/solution.py --pretrained  # плюс bge-m3 (~2.3 ГБ, нужен transformers)
```

## Что получилось у эталона

1200 шагов, 88 с на CPU ноутбука, снимок корпуса `content/data/course-search.json`:

| метод | фрагменты r@1 | вопросы r@1 | r@5 | r@10 |
|---|---|---|---|---|
| TF-IDF по словам | 0.95 | 0.49 | 0.78 | 0.86 |
| TF-IDF по основам | 0.94 | 0.53 | 0.83 | 0.90 |
| bi-encoder (наш, 0.5 М, 1.5 мин) | 0.91 | 0.35 | 0.59 | 0.71 |
| гибрид 0.2 · наш + 0.8 · TF-IDF | 0.95 | 0.55 | 0.83 | 0.91 |
| bge-m3 (568 М, предобучена) | 0.68 | 0.61 | 0.88 | 0.94 |
| гибрид 0.5 · bge-m3 + 0.5 · TF-IDF | 0.94 | 0.61 | 0.89 | 0.95 |

«Фрагменты» — 300 кусков по 8 слов из абзацев. Какие выводы из этого стоит сделать:

- **Мешок слов — сильный соперник.** Когда в запросе есть слова документа, TF-IDF находит его почти всегда. Наша
  модель за полторы минуты на 210 тыс. символов не обгоняет его ни на фрагментах, ни на вопросах. Плотной модели нужны
  данные: bge-m3 предобучали на сотнях миллионов пар.
- **Обученная модель и мешок слов ошибаются по-разному**, поэтому гибрид лучше каждого. Так устроен почти любой поиск
  в проде (BM25 + dense, `iv-retrieval-05`).
- **У bge-m3 фрагменты хуже, чем у TF-IDF** (0.68): обрывок из 8 слов без начала и конца для неё — плохой запрос, а
  для мешка слов — идеальный. Смысловая модель выигрывает на вопросах, сформулированных своими словами.
- **Анизотропия.** До обучения средний косинус двух случайных абзацев 0.18, после — 0.03 (визуализация выше). Чем
  ближе к нулю, тем лучше «чужие» пары отличаются от «своих».
- Recall@5 по вопросам растёт до ~0.66 к шагу 600, а к шагу 1200 падает до 0.59, хотя лосс ICT продолжает падать.
  Модель начинает решать именно задачу ICT (точные куски), а не «смысловой» поиск. Обычное лечение — больше данных,
  dropout, ранняя остановка по отложенной выборке.

## Критерии готовности

- `ict_pair`: запрос — 6 … 14 слов подряд, окно бывает в любом месте абзаца, кусок вырезан примерно в 90 % пар,
  короткий абзац не ломает функцию;
- `idf_weights`: df считается по документам, а не по вхождениям; `tfidf_vectors`: tf × idf, L2, пустой текст — нули;
- `hit_at_k` с несколькими правильными документами;
- три шага `train_step` совпадают с эталоном (лосс и веса);
- 40 шагов на 16 абзацах: фрагмент находит свой абзац в ≥ 75 % случаев.

Запуск тестов: `llmlab test B20-mini-search`.
