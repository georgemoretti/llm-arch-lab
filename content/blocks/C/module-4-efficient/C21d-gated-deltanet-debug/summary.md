## TL;DR

Частая «оптимизация» рекуррентного слоя: обновить состояние в цикле, а выход посчитать одним умножением после
цикла, $o = q\,S_T$. Тогда каждый запрос читает состояние, в которое уже записаны будущие токены куска:
генерация по одному токену верна, prefill — нет (кроме последнего токена), а при обучении модель подсматривает
ответ. Каждый $q_t$ должен читать своё $S_t$.

## Формула

$$o_t = S_t^\top q_t,\quad S_t \text{ — состояние после токена } t;\qquad q_t^\top S_T \text{ — утечка токенов } t{+}1..T$$

## Формы тензоров

```
цикл: S_t [B,H,dk,dv] → o_t [B,H,dv] → stack → [B,H,T,dv]   (не einsum(q [B,H,T,dk], S_T))
```

## Что поменялось относительно C21

Ничего: та же задача, найдена и исправлена утечка будущего через чтение итогового состояния.
