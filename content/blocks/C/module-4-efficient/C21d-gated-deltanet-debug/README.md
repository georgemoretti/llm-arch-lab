# C21d. Отладка: Gated DeltaNet генерирует верно, а при prefill подглядывает в будущее

## Зачем это нужно

У рекуррентных слоёв два режима: генерация (по одному токену, с переносом состояния) и prefill / обучение
(весь кусок сразу). Если они расходятся, модель на обучении видит одно, а на инференсе — другое. Самое
коварное: утечка будущего при обучении даёт **слишком хороший** лосс — модель «учится» подсматривать
ответ, и это замечают только по провалу на генерации.

## Что поменялось относительно C21

Функции те же — `l2norm`, `gated_delta_rule`, `GatedDeltaNet`. Код написан кем-то другим, кто хотел
ускорить цикл. В нём **одна** ошибка.

## Формула

$$S_t = e^{g_t} S_{t-1}(I - \beta_t k_t k_t^\top) + \beta_t k_t v_t^\top,\qquad o_t = S_t^\top q_t / \sqrt{d_k}$$

## Формы тензоров

```
q,k [B,H,T,dk], v [B,H,T,dv], β,g [B,H,T] → out [B,H,T,dv], state [B,H,dk,dv]
```

## Симптом

- итоговое состояние после последовательности — правильное, перенос состояния между вызовами работает;
- если подавать токены **по одному**, каждый выход совпадает с эталоном;
- если подать кусок из нескольких токенов, совпадает только выход **последнего** токена куска;
- выход в ранней позиции меняется, если изменить токены после неё.
