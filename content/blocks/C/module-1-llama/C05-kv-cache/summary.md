## TL;DR

KV-cache хранит k (уже после RoPE) и v всех прошлых токенов по каждому слою, чтобы при генерации
считать проекции только для новых токенов. Это корректно, потому что из-за causal-маски прошлые
k, v не зависят от будущего. Три вещи, которые нужно сделать точно: позиции новых токенов
начинаются с длины кеша (`start = cache.seq_len` до обновления); маска прямоугольная `[T, S]`,
сдвинутая к правому нижнему углу; в кеш идут `H_kv` голов до `repeat_kv`. Проверка — пошаговая
генерация == полный прогон.

## Формула

$$p_i = S_0 + i,\quad q_i = R_{p_i} W_Q x_i,\quad k_i = R_{p_i} W_K x_i,\quad K \leftarrow [K_{\text{cache}}; k]$$

$$M = \texttt{tril}(\text{ones}(T, S),\ \text{diagonal} = S - T),\qquad \text{out} = \operatorname{softmax}(qK^\top/\sqrt{D} + M)\,V$$

## Формы тензоров

```
x [B,T,C], start = cache.seq_len → positions [T] = start..start+T−1 → cos, sin [T,D]
q [B,H,T,D] (RoPE);  k, v [B,H_kv,T,D] (RoPE на k) → cache.update → K, V [B,H_kv,S,D]
repeat_kv → [B,H,S,D];  scores [B,H,T,S] + маска [T,S] → out [B,T,C]
```

## Что поменялось относительно C04

Attention получает только новые токены и кеш прошлых. Добавились RoPE с позициями, сдвинутыми на
длину кеша, хранение k/v между вызовами и прямоугольная маска `[T, S]` со сдвигом. Формула
attention та же — меняется лишь то, откуда берутся K и V и какие позиции у запросов.
