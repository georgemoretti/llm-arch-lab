# Импорт базы вопросов с собеседований

Как сырые вопросы пользователя из `data/interview_raw/` превращаются в вопросы курса в
`content/questions/interview-*.yaml`. Сырые файлы — личные данные: они в `.gitignore`, и их текст
**никуда в репозиторий не копируется** — ни целиком, ни цитатами (репозиторий публичный).

## Конвейер

```
data/interview_raw/*.md|txt|csv|json        (не в git)
        │  llmlab questions import            детерминированно: парсинг → нормализация → дедупликация
        ▼
.llmlab/questions_import/raw.jsonl          (не в git) ref, текст, разделы, файл:строка, дубли
        │  llmlab questions batch -n 50       следующая неразмеченная пачка
        ▼
разметка + переформулировка                 агент (Claude Code) или человек, пачками по ~50
        ▼
content/questions/interview-*.yaml          (в git) свой текст + эталонный ответ + source_ref
        │  llmlab questions status / check    что осталось; нет ли дословных совпадений с сырым
        ▼
вкладка «Interview», вкладка «Вопросы» задачи, конспекты, квизы модулей
```

Разметку можно прервать в любой момент: «размечено» = хэш сырого вопроса есть в `source_ref`
какого-то вопроса в `content/questions/`. Новая сессия начинает с `llmlab questions batch`.

## Парсинг (`llmlab/questions/importer.py`)

| формат | что считается вопросом | раздел (`section`) |
|---|---|---|
| `.md` | пункт списка (`-`, `*`, `•`, `1.`, `1)`) или строка, оканчивающаяся на `?` | стек заголовков `##…######` над строкой; заголовок `#` — название документа, в раздел не входит |
| `.txt` | каждая непустая строка (маркер списка снимается) | — |
| `.csv` | колонка `question`/`вопрос`/`q`/`text`, иначе первая; разделитель определяется автоматически | колонка `topic`/`тема`/`section` |
| `.json` | список строк или объектов с `question`/`вопрос`; допускается `{"…": [...]}` | — |
| `.xlsx` и прочее | пропускается с предупреждением — сохрани как `.csv` | — |

Ответы (`answer`/`ответ` в csv/json) сохраняются в `raw.jsonl` как подсказка разметчику.

**Нормализация и дубли.** Ключ дубля — текст в нижнем регистре, `ё → е`, без пунктуации и лишних
пробелов. `ref = sha1(ключ)[:10]`. Точные дубли схлопываются (места повторов — в `duplicates`).
Смысловые дубли («что такое X» / «зачем нужен X» / «как работает X») объединяет разметчик: один вопрос
курса может покрывать несколько `ref`.

## Маппинг в схему `content/questions`

```yaml
- id: iv-kvcache-01            # iv-<тема>-NN
  topic: kv-cache              # тема курса или other
  tags: [inference]            # подтема для фильтров (обязательно для topic: other: rag, agents, …)
  tasks: [C05-kv-cache, C-Q1-llama-quiz]   # задачи и квиз модуля, если тема есть в курсе
  difficulty: medium
  kind: open                   # open | mcq | code-reading
  question: "…"                # СВОЯ формулировка
  answer: "…"                  # СВОЙ эталонный ответ (в сырой базе ответов нет)
  source: user-db
  source_ref: [a1b2c3d4e5, …]  # какие сырые вопросы покрыты
```

- **topic.** Если вопрос про то, что курс разбирает (attention, позиции, KV-cache, инференс, нормализация,
  MoE, обучение LLM, токенизация и генерация как вход/выход декодера), — тема курса; иначе `topic: other` и
  подтема в `tags` (`rag`, `retrieval`, `agents`, `evals`, `prompting`, `embeddings`, `fine-tuning`,
  `nlp-pipelines`, `classic-ml`, …). Такие вопросы не выбрасываются: они есть во вкладке Interview
  (фильтр «вне курса») и в SRS.
- **tasks.** Только если задача действительно отвечает на вопрос. Плюс квиз модуля (`C-Qn-…`), чтобы
  вопрос попал в квиз. Вопросы без задач видны только во вкладке Interview.
- **difficulty.** easy — определение; medium — механизм/сравнение; hard — расчёт, дизайн системы, тонкий
  эффект.
- **kind.** `mcq` — когда у вопроса есть один проверяемый ответ (расчёт, выбор из вариантов); остальное `open`.
- **Своими словами.** Вопрос переформулируется (часто объединяя несколько сырых), ответ пишется с нуля.
  `llmlab questions check` сравнивает тексты с сырыми (difflib, порог 0.9) и падает на почти дословных.

## Команды

```bash
llmlab questions import [пути…]   # по умолчанию data/interview_raw/
llmlab questions status           # размечено / осталось / темы
llmlab questions batch -n 50      # следующая пачка для разметки
llmlab questions check            # нет ли дословных копий сырого текста
```
