# C17. Multi-Token Prediction: учим модель смотреть на несколько токенов вперёд

## Зачем это нужно

Обычная языковая модель на каждой позиции учится предсказывать **один** следующий токен. Сигнал
обучения «близорукий»: чтобы угадать $t_{i+1}$, часто достаточно локальных паттернов, и модели не
приходится заранее «планировать» дальше.

Multi-Token Prediction (MTP) добавляет к модели $D$ маленьких модулей: модуль глубины $k$
предсказывает токен $t_{i+k+1}$. DeepSeek-V3 использует $D = 1$ (`num_nextn_predict_layers = 1`):
основная голова предсказывает $t_{i+1}$, MTP-модуль — $t_{i+2}$. Что это даёт:

- **больше сигнала** при обучении: на каждой позиции — несколько целей, а градиент MTP-loss идёт и в
  основную модель, заставляя её скрытые состояния кодировать будущее;
- **спекулятивное декодирование** при инференсе: MTP-модуль дешёво предлагает следующий-следующий
  токен, основная модель проверяет его за тот же шаг — по отчёту DeepSeek-V3, второй токен
  принимается в 85–90 % случаев, и генерация идёт примерно в 1.8 раза быстрее (TPS);
- при обычном инференсе модули можно просто выбросить — основная модель от них не зависит.

Ключевая деталь DeepSeek-V3 (в отличие от более ранних вариантов MTP с независимыми головами) —
модули идут **цепочкой** и сохраняют причинность: глубина $k$ получает скрытое состояние глубины
$k - 1$ и эмбеддинг уже известного токена $t_{i+k}$.

## Что поменялось относительно C06

| | основная модель (C06) | + MTP |
|---|---|---|
| цели на позиции $i$ | $t_{i+1}$ | $t_{i+1}$ и $t_{i+k+1}$ для $k = 1..D$ |
| новые модули | — | на глубину: `enorm`, `hnorm`, `eh_proj` ($2C \to C$), блок трансформера, норма |
| эмбеддинг и `lm_head` | свои | **общие** с MTP-модулями |
| loss | $L_{\text{main}}$ | $L_{\text{main}} + \frac{\lambda}{D}\sum_{k} L_k$ (у V3 $\lambda = 0.3$ первые 10T токенов, затем 0.1) |

## Формула

$h^0 = h$ — выход основной модели (до финальной нормы). Для глубины $k = 1..D$ и позиции $i$:

$$
h'^{\,k}_i = W_{eh}\,\big[\operatorname{RMSNorm}(\operatorname{Emb}(t_{i+k}))\ ;\ \operatorname{RMSNorm}(h^{k-1}_i)\big],\qquad
h^{k}_{0..T-k-1} = \operatorname{Block}_k\big(h'^{\,k}_{0..T-k-1}\big)
$$

$$
P^{k}_{i} = \operatorname{softmax}\big(\operatorname{lm\_head}(\operatorname{norm}_k(h^k_i))\big) \ \text{— предсказание } t_{i+k+1},
\qquad
L_k = \operatorname{CE}\big(P^k_{0..T-k-2},\ t_{k+1..T-1}\big)
$$

Позиций на глубине $k$ — $T - k$ (у последних $k$ позиций нет известного $t_{i+k}$), а у последней
позиции глубины ещё и нет цели. В статье DeepSeek-V3 конкатенация записана как $[h ; \text{Emb}]$; в коде
инференса (vLLM) — $[\text{Emb} ; h]$, и веса `eh_proj` соответствуют коду. Здесь — как в коде.

## Формы тензоров

```
h_main                         [B, T, C]       выход основной модели
tokens                         [B, T]
глубина k (k = 1..D):
  h_prev = h[:, :T−k]          [B, T−k, C]     (для k = 1 — h_main; дальше — выход глубины k−1)
  e = embed(tokens[:, k:])     [B, T−k, C]
  x = eh_proj(cat(enorm(e), hnorm(h_prev)))    [B, T−k, 2C] → [B, T−k, C]
  h = block(x)                 [B, T−k, C]
  logits_k = lm_head(norm(h))  [B, T−k, V]
loss:
  L_main = CE(main_logits[:, :−1], tokens[:, 1:])
  L_k    = CE(logits_k[:, :−1],    tokens[:, k+1:])
  total  = L_main + λ/D · Σ L_k
```

## Задание

В `solution.py` (рабочая копия в `workspace/C17-mtp/`) реализуй:

1. `MTPModule.forward(h_prev, emb_next)` — конструктор дан (`enorm`, `hnorm`, `eh_proj`, `block` —
   Pre-Norm блок из C08, `norm`);
2. `mtp_logits(h_main, tokens, embed, lm_head, modules)` → список `[B, T − k, V]`;
3. `mtp_loss(main_logits, mtp_logits_list, tokens, lam)` → `(total, L_main, [L_k])`.

## Критерии готовности

- модуль: `eh_proj([enorm(emb) ; hnorm(h)])` → блок;
- формы `[B, T − k, V]`; токен $j$ влияет на глубину $k$ только начиная с позиции $j - k$;
- глубины связаны цепочкой; эмбеддинг и голова общие (вызываются по разу на глубину);
- loss совпадает с ручным расчётом; градиент MTP доходит до `h_main` (кроме последней позиции).
