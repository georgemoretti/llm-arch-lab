# Attention: одна голова с causal-маской

## Зачем это нужно

После A15 каждая позиция знает свой токен и свой номер, но ничего не знает о соседях. В A10 соседей
подавало окно фиксированной длины: 4 символа, склеенные в один вектор. Окно не может быть длинным
(вектор растёт с длиной окна), а важный для предсказания символ может стоять на 30 позиций назад.

**Attention** решает это иначе. Каждая позиция строит три вектора:

- **запрос** $q$ — что я ищу в прошлом;
- **ключ** $k$ — по какому признаку меня можно найти;
- **значение** $v$ — что я передам тому, кто меня нашёл.

Позиция сравнивает свой запрос с ключами всех позиций (скалярное произведение), превращает оценки в
веса через softmax и складывает значения с этими весами. Длина контекста больше не зашита в веса: одна и
та же голова работает на последовательности из 5 и из 500 позиций.

Языковая модель учится предсказывать следующий токен, поэтому позиции $t$ нельзя смотреть на позиции
после неё: там лежит ответ. Это запрещает **causal-маска**. Нижний треугольник матрицы оценок разрешён,
верхний запрещён.

## Что поменялось относительно A15

| | A15 | A16 |
|---|---|---|
| что знает позиция $t$ | свой токен и номер | взвешенную сумму значений позиций $0 \dots t$ |
| сколько соседей | ни одного | все прошлые, веса выбираются по содержимому |
| размер контекста | — | любой до `block_size`, веса от него не зависят |

## Формула

$$
\operatorname{Attention}(Q, K, V) = \operatorname{softmax}\!\Big(\frac{Q K^{\top}}{\sqrt{D}} + M\Big) V,
\qquad
M_{ij} =
\begin{cases} 0, & j \le i,\\ -\infty, & j > i. \end{cases}
$$

Зачем делить на $\sqrt{D}$. Если компоненты $q$ и $k$ независимы со средним 0 и дисперсией 1, то
$q \cdot k = \sum_{d=1}^{D} q_d k_d$ имеет дисперсию $D$. При $D = 64$ типичные оценки порядка $\pm 8$, и
softmax почти one-hot: один ключ получает весь вес, а градиенты остальных почти нулевые. Деление на
$\sqrt{D}$ возвращает дисперсию к 1.

Маска ставится **до** softmax значением $-\infty$: $e^{-\infty} = 0$, и запрещённые ключи получают вес
ровно 0, а оставшиеся веса по-прежнему суммируются в 1.

## Формы тензоров

```shapes
x [B, T, C]
fork
> query: Linear C → D
q [B, T, D]
branch
> key: Linear C → D
k [B, T, D]
branch
> value: Linear C → D
v [B, T, D]
join
> q @ kᵀ / √D
scores [B, T, T] — строка: запрос, столбец: ключ
> masked_fill(верхний треугольник, −inf)
> softmax по ключам (dim = −1)
weights [B, T, T] — строки суммируются в 1
> weights @ v
out [B, T, D]
axis D = head_size
```

## Задание

В `solution.py` (рабочая копия в `workspace/A16-attention/`):

1. `causal_mask(T)` → bool `[T, T]`, `True` — можно смотреть.
2. `attention(q, k, v, mask=None)` → `(out, weights)`.
3. `AttentionHead.forward(x)`: три проекции, маска `self.mask[:T, :T]` для текущей длины, attention.

`F.scaled_dot_product_attention` и `nn.MultiheadAttention` запрещены: тесты используют их как эталон.
Здесь одна голова размера `head_size`. В C00 голов станет несколько: та же операция параллельно в
нескольких подпространствах.

## Критерии готовности

- маска — нижний треугольник с диагональю, тип `bool`;
- без маски и с маской выход совпадает с `F.scaled_dot_product_attention`, каждая строка весов
  суммируется в 1, веса будущих ключей ровно 0, выход позиции 0 равен `v[0]`;
- размер выхода берётся из `v`, большие оценки не дают `nan`;
- голова совпадает с эталоном при `T < block_size`;
- изменение входа после позиции $t$ не меняет выход на позициях $\le t$; примеры батча независимы.
