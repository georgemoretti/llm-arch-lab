# C00. Causal Multi-Head Self-Attention (как в GPT-2)

## Зачем это нужно

Языковая модель предсказывает следующий токен по предыдущим. Чтобы предсказание в позиции
*t* учитывало контекст, каждому токену нужен способ «собрать» информацию с других позиций —
причём с разной силой: местоимение должно смотреть на существительное, к которому относится,
а не на все слова подряд. Self-attention решает это так: каждый токен формирует **запрос**
(query), каждый токен публикует **ключ** (key) и **значение** (value); вес, с которым позиция
*t* берёт значение позиции *s*, определяется сходством запроса *t* с ключом *s*.

Два уточнения превращают это в блок GPT-2:

- **Causal** — при обучении модель видит всю последовательность сразу, но позиция *t* не
  должна подглядывать в позиции > *t*, иначе задача «предскажи следующий токен» становится
  тривиальной. Это обеспечивает нижнетреугольная маска.
- **Multi-head** — вместо одного распределения внимания считаем *H* независимых в
  подпространствах размера *D = C / H*. Одна голова может следить за синтаксисом, другая —
  за предыдущим токеном и т. д. Число параметров при этом не растёт.

## Что поменялось относительно GPT-2

Ничего — это **отправная точка** блока C. Модуль, который ты напишешь, совпадает с
attention-слоем из `llmlab/core/gpt2.py` (те же имена параметров `c_attn`, `c_proj`).
Дальше по курсу именно его будем менять:

| что | GPT-2 (здесь) | позже |
|-----|---------------|-------|
| позиции | обучаемые эмбеддинги на входе модели, attention о них не знает | RoPE прямо внутри attention (C03) |
| K и V | свои у каждой головы | общие для группы голов — GQA/MQA (C04), латентное сжатие — MLA (C16) |
| маска | полная causal | скользящее окно (C07), разреженная (C18) |
| softmax-внимание | O(T²) | линейное внимание и гибриды (C20–C22) |

## Формула

Для одной головы, с матрицами $Q, K, V \in \mathbb{R}^{T \times D}$:

$$
\operatorname{Attn}(Q, K, V) = \operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{D}} + M\right) V,
\qquad
M_{ts} = \begin{cases} 0, & s \le t \\ -\infty, & s > t \end{cases}
$$

- $QK^\top / \sqrt{D}$ — матрица сходства «запрос × ключ». Деление на $\sqrt{D}$ держит
  дисперсию логитов около 1 независимо от размера головы, иначе softmax насыщается.
- $M$ — causal-маска: $e^{-\infty} = 0$, поэтому будущие позиции получают нулевой вес, а
  разрешённые по-прежнему суммируются в 1.
- softmax берётся **по ключам** (по строке): для каждого запроса — распределение по позициям.

Multi-head: $\operatorname{MHA}(X) = \operatorname{Concat}(\text{head}_1, \dots, \text{head}_H)\, W_O$,
где $\text{head}_h = \operatorname{Attn}(X W_Q^{(h)}, X W_K^{(h)}, X W_V^{(h)})$. На практике все
$W_Q^{(h)}$ (и K, V) склеены в одну матрицу `c_attn` размера $C \times 3C$.

## Формы тензоров

```
x                         [B, T, C]
  │ c_attn (Linear C → 3C)
  ▼
qkv                       [B, T, 3C]
  │ split по последней оси → q | k | v
  ▼
q, k, v                   [B, T, C]   каждый
  │ view(B, T, H, D)       — C разрезаем на H голов по D
  │ transpose(1, 2)        — головы становятся «батчевой» осью
  ▼
q, k, v                   [B, H, T, D]
  │ q @ kᵀ / √D
  ▼
scores                    [B, H, T, T]   строка t — запрос t, столбец s — ключ s
  │ + causal mask, softmax(dim=-1)
  ▼
weights                   [B, H, T, T]   каждая строка суммируется в 1
  │ @ v
  ▼
out                       [B, H, T, D]
  │ transpose(1, 2) → [B, T, H, D], contiguous().view(B, T, C)
  │ c_proj (Linear C → C)
  ▼
y                         [B, T, C]
```

B — батч, T — длина последовательности, C — `d_model`, H — `n_heads`, D = C / H.

## Критерии готовности

- формы выходов верные;
- веса внимания в каждой строке суммируются в 1;
- позиция 0 видит только себя, изменение будущих токенов не меняет прошлые выходы;
- выход численно совпадает с эталоном (`atol=1e-5`), в том числе при D = 64, T = 1 и без bias;
- примеры батча не влияют друг на друга, градиент доходит до всех параметров.
