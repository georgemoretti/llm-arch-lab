## TL;DR

MoE-слой = роутер + $E$ экспертов-FFN; каждый токен проходит через своих $k$ экспертов, их выходы
складываются с весами роутера. Наивно (каждый эксперт на всех токенах) — правильно, но в $E/k$ раз
дороже. Правильно — диспетчеризация: разложить назначения в $N \cdot k$ слотов, отсортировать по
эксперту, прогнать каждого эксперта только на его токенах и вернуть вклады через `index_add_`
(сложение, не запись: у токена $k$ вкладов). Невыбранные эксперты не считаются. Слой возвращает и
логиты роутера — для aux loss.

## Формула

$$y_n = \sum_{j=1}^{k} w_{n,j}\,\text{FFN}_{e_{n,j}}(x_n)$$

## Формы тензоров

```
h [N,C] → indices, weights [N,k] → слоты [N·k] → argsort по эксперту → expert_e(h[tok_e]) [n_e,C]
→ out.index_add_(0, tok_e, w·y) → [N,C] → [B,T,C]
```

## Что поменялось относительно C06

FFN блока заменён MoE-слоем: свой набор из $k$ экспертов на токен, параметров в $E$ раз больше,
вычислений — как у $k$ экспертов. Attention и нормы те же.
