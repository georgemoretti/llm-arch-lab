## TL;DR

Softmax роутера — по оси экспертов (`dim=-1` у `[N, E]`): у каждого токена своё распределение.
С `dim=0` оценка зависит от остальных токенов батча — маршрут меняется от соседей, при генерации по
одному токену роутинг не совпадает с обучением. Перенормировка top-k эту ошибку маскирует (сумма
весов всё равно 1), поэтому проверять нужно независимость от батча и совпадение top-k с top-k логитов.

## Формула

$$s_{n,e} = \frac{e^{\ell_{n,e}}}{\sum_{j=1}^{E} e^{\ell_{n,j}}}\quad(\text{а не }\textstyle\sum_{m=1}^{N} e^{\ell_{m,e}})$$

## Формы тензоров

```
logits [N, E] → softmax(dim=-1) → scores [N, E], scores.sum(-1) == 1
```

## Что поменялось относительно C12

Ничего в архитектуре: это C12 с softmax по неверной оси. Урок — тест «маршрут токена не зависит от
батча» ловит то, что не ловят проверки форм и сумм.
