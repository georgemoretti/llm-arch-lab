# Byte-level BPE: обучение словаря слияний

## Зачем это нужно

В A10 словарём были 61 символ корпуса. Для одного текста этого хватает, но настоящей модели так жить
нельзя. Любой символ, которого не было при обучении (эмодзи, иероглиф, буква «ё»), становится
неизвестным. А последовательности получаются длинными: на каждый символ уходит позиция в контексте и
шаг генерации. Словарь из целых слов решает вторую проблему и обостряет первую: слов бесконечно много.

**BPE (byte pair encoding)** находит середину между этими крайностями. Алгоритм начинает с
минимального словаря и много раз сливает самую частую пару соседних токенов в новый токен. Частые
слова и их куски («ст», « и», «ается») быстро становятся одним токеном. Редкое слово разбивается на
несколько частых кусков, но разбить его можно всегда.

**Byte-level** значит, что стартовый словарь — не символы, а 256 значений байта. Любой текст в UTF-8 —
последовательность байтов, поэтому неизвестных токенов не бывает в принципе. Так устроены токенизаторы
GPT-2, Llama 3 и большинства современных LLM.

## Что поменялось относительно A10

| | A10 | A11 |
|---|---|---|
| стартовые единицы | символы корпуса (61) | байты UTF-8 (всегда 256) |
| словарь | фиксирован текстом | растёт: +1 токен за каждое слияние |
| неизвестный символ | ломает `encode` | невозможен: любой текст — байты |
| длина последовательности | = числу символов | короче: частые куски — один токен |

На русском тексте видно ещё одно отличие. Кириллическая буква в UTF-8 занимает два байта
(`о` = `D0 BE`), поэтому первые слияния собирают из пар байтов сами буквы. Самым первым на нашем
корпусе выучится токен «пробел + первый байт буквы»: это даже не символ, а половина символа. Поэтому
значения словаря — `bytes`, а не `str`.

## Формула

Один шаг обучения на последовательностях $s^{(1)}, \dots, s^{(m)}$:

$$
(a, b)^{*} = \arg\max_{(a, b)}\ \sum_{j} \#\{\,i : s^{(j)}_i = a,\ s^{(j)}_{i+1} = b\,\},
\qquad
\text{merges}[(a, b)^{*}] = 256 + k,
$$

после чего во всех $s^{(j)}$ каждое вхождение пары слева направо заменяется на токен $256 + k$.
Шаг повторяется для $k = 0, 1, \dots$, пока словарь не достигнет `vocab_size`. При равных частотах
выбирается меньшая пара (кортежи сравниваются как в Python), иначе результат зависел бы от порядка
обхода словаря.

Номер слияния — это и **ранг**: токен с меньшим id выучен раньше и при кодировании нового текста будет
применяться раньше (это задача A12).

## Формы тензоров

```shapes
- text: строка → text.encode("utf-8")
seqs [m, n_j] — m последовательностей байтов (списки int 0..255)
> count_pairs: пары соседей внутри каждой
counts [P] — {пара: частота}
> argmax по частоте, при равенстве — меньшая пара
pair [2] — (a, b)
> merge_pair в каждой последовательности → токен 256 + k
seqs [m, n_j′] — n_j′ ≤ n_j
- повторить vocab_size − 256 раз
merges [K] — {(a, b): 256 + k}, K = vocab_size − 256
> build_vocab
vocab [V] — {id: bytes}, V = 256 + K
axis m = число последовательностей (кусков текста)
axis P = число различных пар
axis K = число слияний
```

## Задание

В `solution.py` (рабочая копия в `workspace/A11-bpe-train/`):

1. `count_pairs(seqs)` — словарь `{(a, b): частота}` по всем последовательностям. Пары через границу
   двух последовательностей не считаются: в A13 последовательностями станут отдельные слова.
2. `merge_pair(seq, pair, new_id)` — новый список, где пара заменена слева направо без перекрытий.
3. `train_bpe(seqs, vocab_size)` — `merges` в порядке обучения. `vocab_size < 256` → `ValueError`;
   если пар не осталось, обучение заканчивается раньше.
4. `build_vocab(merges)` — `{id: bytes}`.

Готовые функции BPE (`Counter`, `tokenizers`, `tiktoken`) не нужны: весь алгоритм — около 30 строк.

## Критерии готовности

- `count_pairs` считает перекрывающиеся пары (`[5, 5, 5]` → две пары) и не считает пары через границы;
- `merge_pair([5, 5, 5], (5, 5), 7) == [7, 5]`, входной список не меняется;
- на «aaabdaaabac» слияния совпадают с эталоном; при равных частотах выбирается меньшая пара;
- id новых токенов идут подряд с 256, каждое слияние ссылается только на уже выученные токены;
- на корпусе курса первые 120 слияний совпадают с эталоном, текст сжимается больше чем вдвое;
- склейка байтов токенов обученной последовательности даёт исходный текст байт в байт.

Запуск: `llmlab test A11-bpe-train`.
