## TL;DR

`torch.roll(tgt, 1, dims=1)` — циклический сдвиг: на позицию 0 входа декодера попадает последний токен цели (EOS
или PAD), а не BOS. Обучение проходит отлично (вход всё равно не подсматривает ответ), но при генерации префикс
начинается с BOS, которого модель не видела. Разрыв train/inference ломает первый же токен. Правильно — сдвиг с
заполнением: `cat([BOS, tgt[:, :-1]])`.

## Формула

$$\text{roll: } [y_{T-1}, y_0, \dots, y_{T-2}] \quad\text{вместо}\quad [\text{BOS}, y_0, \dots, y_{T-2}]$$

## Формы тензоров

```
tgt [B,T] → cat([BOS [B,1], tgt[:, :-1]]) → tgt_in [B,T]
```

## Что поменялось относительно B05

Ничего в механизме: найдено расхождение входа декодера при обучении и генерации. Поймали его тест `shift_right` и
smoke test «запомни 6 пар и сгенерируй».
