# Расписание learning rate и gradient clipping

## Зачем это нужно

Постоянный learning rate почти никогда не оптимален. Обучение LLM управляется двумя
дополнительными деталями, и обе встречаются в каждом серьёзном цикле обучения.

**Warmup.** В начале обучения моменты Adam ещё не накоплены, веса случайные, градиенты большие и
шумные. Полный lr на первых шагах может отправить модель в плохую область, откуда она не выберется,
и лосс взлетит до nan. Поэтому lr поднимают от нуля до максимума за первые сотни или тысячи шагов.

**Decay.** К концу обучения большой lr мешает сойтись: модель прыгает вокруг минимума. Cosine
decay плавно опускает lr до небольшого `min_lr`. Альтернатива — **WSD** (warmup → долгая
постоянная фаза → короткий спад). С ней удобно продолжать обучение и сравнивать чекпойнты (MiniCPM,
ссылка во вкладке «Чтение»).

**Gradient clipping.** Иногда один батч даёт аномально большой градиент. Чтобы такой выброс не
испортил веса, перед шагом оптимизатора градиенты масштабируют так, чтобы их **общая** норма не
превышала порог. Направление шага при этом сохраняется.

Пример реальных значений: Llama 2 — 2000 шагов warmup, cosine до 10% от пикового lr, clipping с
порогом 1.0 (Touvron et al., 2023, раздел 2.2).

## Что поменялось относительно A07

| | A07 | A08 |
|---|---|---|
| lr | константа в конструкторе | функция от номера шага |
| градиенты перед `step()` | как есть | глобальная норма ≤ max_norm |
| порядок шага | backward → step | backward → **clip** → **lr = lr_at(t)** → step |

## Формула

Шаг $t$ считается с нуля, $W$ — число шагов warmup, $T$ — общее число шагов:

$$
\eta(t) =
\begin{cases}
\eta_{\max}\,\dfrac{t + 1}{W}, & t < W,\\[6pt]
\eta_{\min} + \dfrac{\eta_{\max} - \eta_{\min}}{2}\Big(1 + \cos\big(\pi\,\tfrac{t - W}{T - W}\big)\Big), & W \le t < T,\\[6pt]
\eta_{\min}, & t \ge T.
\end{cases}
$$

$t + 1$ в warmup нужен, чтобы уже первый шаг не был пустым.

**Clipping по глобальной норме.** Все градиенты всех параметров рассматриваются как один длинный
вектор:

$$
\lVert g\rVert = \sqrt{\textstyle\sum_{p}\sum_i g_{p,i}^2}, \qquad
g \leftarrow g \cdot \min\Big(1,\ \frac{c}{\lVert g\rVert + \varepsilon}\Big).
$$

Если обрезать каждый тензор отдельно, разные параметры уменьшатся в разное число раз, и шаг повернётся.

## Формы тензоров

```shapes
g₁ [A, B] — градиент первого параметра
g₂ [C] — градиент второго
> Σ квадратов всех элементов всех градиентов, √
‖g‖ [] — одна глобальная норма
> coef = min(1, c / (‖g‖ + ε))
> g_p ← g_p · coef — один coef на все параметры
g₁ [A, B] — та же форма, направление то же
```

## Задание

В `solution.py` (рабочая копия в `workspace/A08-lr-schedule/`):

1. `lr_at(step, max_lr, warmup_steps, total_steps, min_lr=0)` по формуле выше. При `warmup_steps = 0`
   деления на ноль быть не должно.
2. `clip_grad_norm_(params, max_norm, eps=1e-6)`: глобальная норма, обрезка градиентов на месте, если
   норма больше порога. Возвращает норму **до** обрезки числом `float`. Параметры без `.grad` пропускаются.

`nn.utils.clip_grad_norm_` и `torch.optim.lr_scheduler` использовать нельзя.

## Критерии готовности

- warmup линейный, шаг 0 ненулевой, на шаге `warmup − 1` ровно `max_lr`;
- cosine: `max_lr` сразу после warmup, $(\eta_{\max} + \eta_{\min})/2$ в середине, `min_lr` после конца;
- нет скачков на стыке, lr не убывает в warmup и не растёт после;
- `warmup_steps = 0` работает;
- clipping совпадает с `nn.utils.clip_grad_norm_`: та же норма, те же градиенты;
- маленькие градиенты не меняются, направление шага сохраняется.
