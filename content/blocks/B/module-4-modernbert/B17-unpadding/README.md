# Unpadding: батч без PAD, cu_seqlens и блочно-диагональная маска

## Зачем это нужно

Тексты в батче разной длины, и до сих пор (B01, B10, B16) мы дополняли их PAD до самого длинного. На PAD-позициях
модель честно считает всё: линейные слои, attention, FFN, а результат потом выбрасывает. Если в батче один текст на 512
токенов, а остальные по 80, на паддинг уходит три четверти работы линейных слоёв и ещё больше в attention.

ModernBERT поступает иначе: убирает PAD **до** первого слоя (unpadding). Настоящие токены всех текстов кладутся в
одну строку длины $N$, а границы текстов хранятся в `cu_seqlens` (cumulative sequence lengths). Линейные слои, нормы и
FFN работают с токенами по отдельности, им всё равно, к какому тексту токен относится. Особого внимания требуют два
места:

- **attention** не должен смешивать тексты: токен видит только свой текст. Flash Attention
  (`flash_attn_varlen_func`) по `cu_seqlens` считает только диагональные блоки. Мы сделаем то же через
  блочно-диагональную маску;
- **позиции RoPE** у каждого текста начинаются с нуля, а не продолжают предыдущий текст.

Та же упаковка (packing) используется при обучении декодеров: короткие примеры SFT склеиваются в одну строку, и
`cu_seqlens` не даёт им видеть друг друга.

## Что поменялось относительно B16

| | B16 | B17 |
|---|---|---|
| вход слоя | `[B, T, C]` с PAD | `[N, C]`, только настоящие токены, текст за текстом |
| маска | `[B, 1, 1, T]` (PAD-ключи) и окно `[T, T]` | блочно-диагональная `[N, N]` по `cu_seqlens` (и окно внутри блока) |
| позиции | `arange(T)` у каждой строки | `packed_position_ids`: 0, 1, … заново у каждого текста |
| работа линейных слоёв | $B \cdot T$ токенов | $N = \sum_b L_b$ токенов |
| работа attention | $B \cdot T^2$ пар | $\sum_b L_b^2$ пар (у Flash Attention) |

Наша маска `[N, N]` — учебная: она проверяет, что упаковка не меняет ответ, но сама занимает $N^2$ памяти. Настоящая
экономия получается, когда ядро вообще не считает внедиагональные блоки.

## Формула

Пусть $L_0, \dots, L_{B-1}$ — длины текстов. Тогда

$$
\text{cu\_seqlens} = [\,0,\ L_0,\ L_0 + L_1,\ \dots,\ N\,], \qquad N = \sum_b L_b,
$$

и текст $b$ занимает в упаковке строки $\text{cu}_b \dots \text{cu}_{b+1} - 1$. Токен $n$ из текста $b(n)$ имеет
позицию $n - \text{cu}_{b(n)}$, а маска упаковки

$$
\text{mask}[i, j] = \big[\, b(i) = b(j) \,\big] \ \wedge\ \big[\, |i - j| \le \lfloor W/2 \rfloor \,\big]_{\text{локальный слой}} .
$$

Экономия от упаковки: $1 - \frac{\sum L_b}{B T}$ в линейных слоях и $1 - \frac{\sum L_b^2}{B T^2}$ в attention.

## Формы тензоров

```shapes
attention_mask [B, T]
> unpad_input
indices [N]
cu_seqlens [B+1]
x [B, T, C]
> pack: flatten(0, 1)[indices]
packed [N, C]
> Wqkv, головы; RoPE по packed_position_ids
q [N, H, D]
> varlen_attention: блочная маска [N, N]
out [N, H, D]
> Wo, FFN … (каждый токен отдельно)
packed [N, C]
> unpack: нули на месте PAD
x [B, T, C]
axis N = число настоящих токенов
```

## Задание

В `solution.py` (рабочая копия в `workspace/B17-unpadding/`) напиши:

1. `unpad_input(attention_mask)` → `(indices, cu_seqlens, max_seqlen)`; `cu_seqlens` — int32.
2. `pack(x, indices)` и `unpack(packed, indices, B, T)`.
3. `packed_position_ids(cu_seqlens)` — позиции с нуля у каждого текста.
4. `varlen_mask(cu_seqlens, window=None)` — блочно-диагональная маска, с окном ±W/2 внутри текста.
5. `varlen_attention(q, k, v, cu_seqlens, window=None)` — attention на упаковке `[N, H, D]`.
6. `padding_savings(attention_mask)` — доли сэкономленной работы.

## Критерии готовности

- `cu_seqlens` = `[0, 3, 5, 11, 15]` для длин 3, 2, 6, 4; паддинг слева и пустой текст тоже работают;
- `pack` → `unpack` возвращает настоящие токены на места, на месте PAD нули;
- позиции начинаются с нуля у каждого текста;
- attention на упаковке совпадает с батчем с паддингом, полное и с окном; правка одного текста не меняет остальные;
- слой attention ModernBERT на упаковке даёт тот же выход, что на батче с паддингом;
- `padding_savings` считает 0.375 и 0.549 на примере из тестов.
