## TL;DR

Относительная позиция посчитана как «запрос минус ключ» вместо «ключ минус запрос». В двунаправленном режиме
половины бакетов меняются местами: модель с нуля это переживёт, а чужие веса — нет. В causal-режиме все прошлые ключи
получают сдвиг ≥ 0, то есть расстояние 0 и один бакет: декодер теряет порядок. Знак сдвига проверяется одним
тестом «ключ слева → первая половина».

## Формула

$$r = j - i \ (\text{ключ} - \text{запрос}),\quad r < 0 \Rightarrow \text{ключ слева}$$

## Формы тензоров

```
k_pos [1,S] − q_pos [T,1] → r [T,S] → bucket → [1,H,T,S]
```

## Что поменялось относительно B13

Ничего в механизме: перепутан порядок вычитания. Его поймали тесты на «слева ≠ справа» и на разный bias прошлых
ключей в causal-режиме.
