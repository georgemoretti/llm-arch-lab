# Отладка: MLA генерирует правильно, но памяти ест как MHA

## Зачем это нужно

Бывают ошибки, которые не меняют ни одного числа на выходе. Модель генерирует ровно то же, что и
эталон, все тесты на корректность проходят — а при длинном контексте вылетает по памяти. В MLA
вся выгода — в том, **что** лежит в кеше, и это легко потерять одной перестановкой строк.

## Что поменялось относительно C16

Архитектура та же — `LatentCache` и `MLAttention` из C16. Код написан кем-то другим, и в нём
**одна** ошибка.

## Формула

$$c = \operatorname{norm}(W_{DKV} x),\qquad k_h = W_{UK}^{(h)} c,\qquad v_h = W_{UV}^{(h)} c$$

## Формы тензоров

```shapes
x [B, T, C]
> kv_a_proj → norm
c [B, T, r]
> …
K, V [B, H, S, ·]
> …
out [B, T, C]
axis r:other = размер латента KV
```

## Симптом

- `forward` без кеша и с кешем (по одному токену, кусками) совпадает с полным прогоном;
- `forward_absorbed` совпадает с `forward` и не вызывает `kv_b_proj`;
- но после длинного prefill память под кеш растёт заметно быстрее, чем обещает MLA: на тех же размерах
  она ближе к обычному MHA-кешу, чем к GQA. Посчитай, сколько чисел на токен лежит в кеше и сколько должно.

Код — в `workspace/C16d-mla-debug/solution.py`. Найди и исправь ошибку.
