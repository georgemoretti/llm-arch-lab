# Отладка: с накоплением градиентов модель учится иначе, чем с большим батчем

## Зачем это нужно

Накопление градиентов должно быть невидимым: 8 микро-батчей по 4 примера дают тот же шаг, что один батч из 32.
Если это не так, гиперпараметры перестают переноситься между машинами. Рецепт подобрали на большой GPU без
накопления, запустили на маленькой с накоплением, и модель учится хуже без видимой причины.

## Что поменялось относительно D03

Ничего: это те же функции, что в D03. Их написал коллега, и в коде **одна** ошибка.

## Формула

$$\mathcal{L} = \frac{1}{N}\sum_{b}\sum_{t \in S_b}\ell_t, \qquad N = \sum_b |S_b| .$$

## Формы тензоров

```shapes
input_ids [B, T]
targets [B, T]
> model
logits [B, T, V]
> CE по меткам, нормировка
loss []
axis B = примеров в микро-батче
axis T:seq = длина
axis V = словарь
```

## Симптом

- `masked_ce_sum` верна, возвращаемый средний лосс и число токенов верны;
- с одним микро-батчем (без накопления) всё совпадает с эталоном, переобучение на одном батче работает;
- если микро-батчи примерно одной длины, градиент почти совпадает с большим батчем;
- если в одном микро-батче длинные ответы (JSON), а в другом короткие (числа), градиент заметно отличается от
  большого батча из тех же примеров. Добавление пустого микро-батча из одних PAD тоже меняет градиент.
