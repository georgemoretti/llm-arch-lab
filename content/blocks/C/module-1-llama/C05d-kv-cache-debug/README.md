# Отладка: с KV-cache генерация расходится с полным прогоном после промпта

## Зачем это нужно

KV-cache — оптимизация, которая не должна менять ни одного числа: с кешем и без модель обязана
выдавать одно и то же. Ошибки в нём особенно неприятны тем, что модель не падает, а генерирует
правдоподобный, но всё более странный текст, и заметить это можно только сравнением с полным
прогоном. Задача — найти такую ошибку по тому, **на каком шаге** начинается расхождение.

## Что поменялось относительно C05

Архитектура та же — `KVCache` и `LlamaAttention` из C05. Код написан кем-то другим, и в нём
**одна** ошибка.

## Формула

$$
p_i = S_0 + i,\qquad q_i = R_{p_i} W_Q x_i,\quad k_i = R_{p_i} W_K x_i,\qquad
M = \texttt{tril}(\text{ones}(T, S),\ S - T)
$$

## Формы тензоров

```shapes
x [B, T, C]
> проекции + RoPE
q [B, H, T, D]
k, v [B, H_kv, T, D]
> cache.update
K, V [B, H_kv, S, D]
> q·Kᵀ/√D
scores [B, H, T, S]
```

Все формы в коде правильные, кеш склеивается верно, маска со сдвигом на месте.

## Симптом

- без кеша выход совпадает с эталоном, будущее не протекает;
- prefill всего промпта в пустой кеш тоже даёт правильный выход;
- но если после промпта генерировать по одному токену (или подавать промпт кусками), то **первый
  кусок совпадает**, а все следующие токены уже расходятся с полным прогоном.
