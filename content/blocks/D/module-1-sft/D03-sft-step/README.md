# Шаг SFT: накопление градиентов с честной нормировкой на токены ответа

## Зачем это нужно

Цикл обучения из A09 почти без изменений годится для SFT, но одна деталь в нём становится важной. Батч SFT редко
помещается в память целиком, поэтому его делят на **микро-батчи** и накапливают градиенты: несколько раз
forward/backward, потом один `optimizer.step()`. Цель — получить тот же градиент, что дал бы один большой батч.

При предобучении это получается само: все строки одной длины, и «среднее по микро-батчу, делённое на число
микро-батчей» равно среднему по большому батчу. В SFT ответы разной длины: в одном микро-батче 30 меченых токенов,
в другом 300. Если усреднить каждый микро-батч отдельно и потом взять среднее средних, токен из короткого
микро-батча весит в 10 раз больше токена из длинного. Градиент перестаёт совпадать с большим батчем и зависит от
того, как примеры разложились по микро-батчам. В 2024 году ровно такая ошибка нашлась в накоплении градиентов
`transformers`: лосс с накоплением заметно расходился с лоссом без него, пока нормировку не исправили (ссылки во
вкладке «Чтение»).

## Что поменялось относительно D02

| | A09 (предобучение) | D03 (SFT) |
|---|---|---|
| лосс микро-батча | `mean` по всем позициям | **сумма** по меченым позициям |
| делитель | число микро-батчей | число меченых токенов **во всём шаге** $N$ |
| строки | одной длины | разной длины, PAD и −100 |

Расписание lr (линейный warmup + cosine, A08) и clipping по глобальной норме — те же. Порядок действий за шаг:
выставить lr → `zero_grad` → накопить → clip → `step`.

## Формула

Пусть шаг состоит из микро-батчей $b = 1 \dots K$, а $S_b$ — множество меченых позиций в микро-батче $b$. Большой
батч оптимизирует средний лосс на токен ответа:

$$
\mathcal{L} = \frac{1}{N} \sum_{b=1}^{K} \sum_{t \in S_b} \ell_t, \qquad N = \sum_{b=1}^{K} |S_b|,
\qquad
\nabla\mathcal{L} = \sum_{b=1}^{K} \nabla\Big(\frac{1}{N}\sum_{t \in S_b} \ell_t\Big).
$$

Значит, каждый микро-батч должен делать `backward` от **суммы** своих лоссов, делённой на общее $N$, известное
заранее (метки есть до прогона модели). Неправильный вариант «среднее средних»:

$$
\tilde{\mathcal{L}} = \frac{1}{K}\sum_{b=1}^{K} \frac{1}{|S_b|}\sum_{t \in S_b} \ell_t
\quad\Rightarrow\quad \text{вес токена} = \frac{1}{K\,|S_b|} \ne \frac{1}{N}.
$$

Он совпадает с правильным, только если все $|S_b|$ равны. При обучении на нескольких GPU та же история: $N$ надо
суммировать по всем устройствам (all-reduce числа токенов), а не усреднять лоссы устройств.

## Формы тензоров

```shapes
input_ids [B, T]
targets [B, T]
> model
logits [B, T, V]
> CE по меткам ≠ −100, сумма
loss_sum []
> / N (токены ответа во ВСЕХ микро-батчах шага) → backward
grad [P]
> × K микро-батчей, затем clip → step
axis B = примеров в микро-батче
axis T:seq = длина (с PAD)
axis V = словарь
axis P = параметров модели
```

## Задание

В `solution.py` (рабочая копия в `workspace/D03-sft-step/`) напиши:

1. `masked_ce_sum(logits, targets) -> (сумма, число меченых позиций)`.
2. `accumulate_gradients(model, micro_batches) -> (средний лосс на токен, N)`.
3. `sft_step(model, optimizer, micro_batches, step, *, max_lr, warmup_steps, total_steps, min_lr, max_norm) -> dict`.

`lr_at` из A08 и `collate` (дополнение PAD справа, метки −100) уже импортированы.

## Критерии готовности

- `masked_ce_sum` — сумма, а не среднее; −100 пропускаются;
- градиент после накопления по микро-батчам разной длины == градиенту большого батча; распознаются «среднее
  средних» и «забыли поделить»;
- микро-батч из одних PAD ничего не меняет; шаг без меток → `ValueError`;
- `sft_step`: lr по расписанию, мусор в `.grad` от прошлого шага стирается, норма — до обрезки; 4 шага == эталон;
- переобучение на одном батче: лосс ниже 0.1 за 60 шагов.
