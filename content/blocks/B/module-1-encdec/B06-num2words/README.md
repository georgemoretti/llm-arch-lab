# Проект: seq2seq «число цифрами → число словами»

## Зачем это нужно

Пора обучить энкодер-декодер целиком. Настоящий перевод требует больших корпусов и часов на GPU, поэтому
возьмём маленькую задачу с той же структурой: **число цифрами → число словами по-русски**.

```
2022    → две тысячи двадцать два
11000   → одиннадцать тысяч
123456  → сто двадцать три тысячи четыреста пятьдесят шесть
```

Задача проще перевода, но в ней есть всё, ради чего придумали seq2seq:

- **разные длины** источника и цели: «100» — три цифры и одно слово, «21» — две цифры и два слова;
- **выравнивание**: каждое слово отвечает за свои цифры, и его нужно найти в источнике (как слово перевода
  ищет свой оригинал);
- **нули молчат**: в «105000» три нуля не дают ни одного слова, но сдвигают смысл остальных цифр;
- **согласование**: «одна тыся**ча**», «две тыся**чи**», «пять тыся**ч**», «одиннадцать тыся**ч**» — форма зависит от
  последних двух цифр группы тысяч, «один» и «два» меняют род.

Чисел от 0 до 999 999 миллион, а учиться будем на 2000 случайных. Остальные модель никогда не видела.
Насколько хорошо она обобщит правила?

## Что поменялось относительно A18

| | A18 (мини-GPT) | B06 (seq2seq) |
|---|---|---|
| данные | один текст, окна со сдвигом | пары «источник → цель», батч собирается с PAD |
| вход декодера | окно текста | `shift_right(цель)`: BOS + цель без последнего токена |
| качество | val loss, образцы генерации | exact match: доля чисел, переведённых целиком без ошибок |
| интерпретация | — | карта cross-attention: какие цифры смотрит каждое слово |

## Формула

Шаг обучения — teacher forcing из B05:

$$
\mathcal{L} = \frac{1}{N_{\text{не PAD}}}\sum_{b,t:\ y_{b,t} \ne \text{PAD}}
\operatorname{CE}_\varepsilon\Big(\operatorname{Seq2Seq}\big(\text{src}_b,\ [\text{BOS}, y_{b,0}, \dots]\big)_t,\ y_{b,t}\Big),
\qquad \varepsilon = 0.1.
$$

Exact match: $\frac{1}{N}\sum_n \big[\operatorname{greedy}(n) = \text{цель}(n)\big]$, сравнение до EOS включительно.
Ответ без EOS — промах: модель, которая не умеет остановиться, ошибается.

## Формы тензоров

```shapes
- pairs: список (id цифр, id слов + EOS), длины разные
> collate: PAD справа до максимума в батче
src [B, S] — S ≤ 6
tgt [B, T] — T ≤ 8
> shift_right(tgt, BOS)
tgt_in [B, T]
> Seq2Seq(src, tgt_in)
logits [B, T, V]
> label_smoothed_ce(logits, tgt), clip 1.0, AdamW
loss []
axis V:wide = 55 токенов: 3 служебных, 10 цифр, 42 слова
```

## Задание

В `solution.py` (рабочая копия в `workspace/B06-num2words/`):

1. `encode_pair(n, stoi)` → (id цифр, id слов + EOS).
2. `collate(pairs)` → `(src, tgt)` с PAD справа.
3. `train_step(model, opt, src, tgt, eps, clip)` → float: один шаг teacher forcing с label smoothing и clip.
4. `exact_match(model, numbers, stoi)` → доля чисел, переведённых целиком.

Данные (`number_to_words`, словарь, разбиение), модель и цикл обучения в `main` готовы. Модель, лосс и
`greedy_decode` — эталоны B05.

Когда тесты пройдут, обучи модель целиком (~25 с на CPU):

```bash
python workspace/B06-num2words/solution.py
```

Эталонный прогон (2000 чисел, 1500 шагов, батч 64, $d_{\text{model}} = 64$, 2 + 2 слоя, 0.24 М параметров): к
шагу 400 exact match на 500 отложенных числах — 97.6 %, к концу — 99.4 %.

## Что посмотреть после обучения

**Карту cross-attention** (вкладка «Визуализация»). У «сто двадцать три тысячи четыреста пятьдесят шесть»
почти диагональ: «сто» смотрит на «1», «двадцать» — на «2» (вес ~0.95). Слово «тысячи» смотрит на
цифры после группы тысяч: модель решает, где кончается группа, по тому, сколько цифр осталось справа. Никто
не учил её выравниванию: оно появилось само из лосса на словах.

**Ошибки.** Из 500 отложенных чисел эталон ошибается на трёх, и все три — короткие: «761» → «семь тысяч
шестьсот одиннадцать», «2580» → «двести пятьдесят тысяч восемьсот». Причина в данных, а не в модели: среди
случайных чисел до миллиона 90 % шестизначных, а трёхзначных — 0.09 %, то есть в обучении их почти нет.
Модель выучила «первая цифра — сотни тысяч». Это **сдвиг распределения**: тестовые данные устроены не так, как
обучающие. Проверь сам, что будет с числом 7.

**Попробуй (по желанию):** выбирай числа так, чтобы длины 1…6 цифр встречались одинаково часто, и сравни
ошибки на коротких числах.

## Критерии готовности

- `encode_pair`: цифры по одной; слова и EOS, без BOS;
- `collate`: PAD справа, тензоры `long`;
- `train_step` совпадает с эталоном за 3 шага (лосс и веса): `shift_right`, PAD игнорируется, clip перед шагом;
- `exact_match`: сравнение до EOS включительно, генерация в eval-режиме, режим модели восстанавливается;
- маленькая модель запоминает 12 чисел на 100 %.
