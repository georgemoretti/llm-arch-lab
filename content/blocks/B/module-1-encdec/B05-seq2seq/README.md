# Seq2seq целиком: teacher forcing, label smoothing, greedy decode

## Зачем это нужно

Энкодер и декодер готовы. Осталось связать их в модель, которая переводит последовательность в
последовательность (sequence-to-sequence), научить её и заставить генерировать. Здесь три идеи.

**Teacher forcing.** При обучении правильный ответ известен целиком. Вместо того чтобы генерировать токен за
токеном, декодеру сразу подают правильный префикс, сдвинутый на одну позицию вправо: `[BOS, y0, y1, …]`. На
позиции $t$ он предсказывает $y_t$, видя (благодаря causal-маске) только `BOS, y0 … y_{t-1}`. Все позиции
считаются за один проход — как у GPT в A18. Сдвиг делает `shift_right`.

**Label smoothing.** Статья учит модель не на one-hot целях, а на сглаженных: правильному токену
вероятность $1 - \varepsilon$, остальное размазано по словарю. Модель перестаёт гнаться за бесконечно
уверенными логитами. Перплексия на обучении от этого хуже, а качество перевода (BLEU) — лучше (§5.4 статьи,
$\varepsilon = 0.1$).

**Генерация.** На инференсе ответа нет. Энкодер читает источник **один раз**, а декодер запускается в цикле:
`[BOS]` → токен → `[BOS, токен]` → следующий… Жадная стратегия берёт argmax. Тексты в батче заканчиваются в
разное время, поэтому закончившим строкам дописывают PAD, а цикл прерывается, когда EOS есть везде.

Ещё одна деталь из §3.4 статьи: одна матрица эмбеддингов на всё — вход энкодера, вход декодера и выходной
слой. Для этого у источника и цели общий словарь (в статье — общий BPE на английский и немецкий).

## Что поменялось относительно A18

| | A18 (мини-GPT) | B05 (seq2seq) |
|---|---|---|
| вход | один текст, предсказываем его продолжение | источник → цель, две последовательности |
| вход декодера | `x` = текст, `y` = тот же текст со сдвигом | `shift_right(tgt)` = `[BOS, y0 …]`, цель `tgt` |
| лосс | cross-entropy | cross-entropy с label smoothing, PAD игнорируется |
| генерация | весь контекст через модель на каждом шаге | энкодер один раз, декодер на растущем префиксе, стоп по EOS |
| общие веса | `wte` = `lm_head` | эмбеддинги энкодера = декодера = `lm_head` |

## Формула

Сглаженная цель и лосс для позиции с правильным токеном $y$, словарь размера $V$:

$$
q_v = (1 - \varepsilon)\,[v = y] + \frac{\varepsilon}{V},
\qquad
\mathcal{L} = -\sum_{v} q_v \log p_v
= (1 - \varepsilon)\,\big(-\log p_y\big) + \varepsilon\,\Big(-\frac{1}{V}\sum_v \log p_v\Big).
$$

Лосс усредняется по позициям, где цель не PAD. Градиент по логитам — тот же $p - q$, что в A04, только с
мягкой целью: модель тянут к $q$, а не к one-hot. Минимум достигается при $p = q$, логиты остаются
конечными.

Это соглашение PyTorch (`label_smoothing` в `F.cross_entropy`) и Szegedy et al. (2016): $\varepsilon/V$ получает
и правильный класс. В fairseq масса $\varepsilon$ делится на $V - 1$ неверных классов — разница мала при большом
$V$.

## Формы тензоров

```shapes
src [B, S]
> encode: encoder, padding_mask
memory [B, S, C]
tgt [B, T] — y0 … y_{T−2}, EOS, PAD…
> shift_right: BOS слева, последний токен долой
tgt_in [B, T]
> decode: decoder(tgt_in, memory, src_mask) → lm_head (= tok.weightᵀ)
logits [B, T, V]
> label_smoothed_ce(logits, tgt, ε, ignore = PAD)
loss [] — скаляр
axis V:wide = словарь
```

## Задание

В `solution.py` (рабочая копия в `workspace/B05-seq2seq/`):

1. `shift_right(tgt, bos_id)` — новый тензор той же формы, вход не меняется.
2. `label_smoothed_ce(logits, target, eps, ignore_index)` — без `F.cross_entropy` (это оракул тестов).
3. `Seq2Seq.encode`, `Seq2Seq.decode`, `Seq2Seq.forward`. Конструктор с общей матрицей готов.
4. `greedy_decode(model, src, max_len)` → `[B, L]`, $L \le$ `max_len`, без BOS, PAD после EOS.

## Критерии готовности

- `shift_right` ставит BOS на позицию 0 и не портит вход;
- лосс совпадает с `F.cross_entropy(label_smoothing=ε, ignore_index=PAD)` при $\varepsilon \in \{0, 0.1, 0.3\}$;
  градиент равен $(p - q)/N$ и нулю на PAD;
- `forward` совпадает с эталоном; логиты позиции $t$ не зависят от входа декодера после $t$;
- `greedy_decode`: энкодер вызывается один раз, PAD после EOS, остановка, когда закончили все, ровно
  `max_len` шагов без EOS, совпадение с эталоном;
- модель запоминает 6 пар «развернуть последовательность», и жадная генерация их воспроизводит.
