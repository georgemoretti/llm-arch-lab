# Тренировочный цикл: батчи, порядок шага, валидация

## Зачем это нужно

Все детали уже есть: модель, лосс, оптимизатор (A07), расписание и clipping (A08). Осталось собрать их
в цикл обучения. Почти все «загадочные» проблемы обучения на деле оказываются ошибками в этом цикле:

- шаг сделан по градиенту прошлых батчей;
- lr выставлен на шаг позже;
- clipping вызван после `step()`, то есть вообще ни на что не влияет;
- валидация идёт с включённым dropout и даёт шумные числа;
- после валидации модель осталась в режиме `eval`, и dropout больше никогда не работает.

Здесь ты напишешь цикл, в котором каждая из этих деталей на своём месте. Есть и проверка, которую
стоит делать первой с любой новой моделью: **переобучиться на одном батче**.

## Что поменялось относительно A03

| | A03 | A09 |
|---|---|---|
| данные | весь набор на каждом шаге | случайные батчи (`get_batch` с генератором) |
| модель | свой MLP на `Value` | любой `nn.Module`, есть dropout |
| шаг | zero_grad → backward → step | + lr по расписанию, + clipping |
| контроль | только train-лосс | валидация в режиме `eval`, история лоссов |
| отладка | — | smoke-тест на одном батче |

## Формула

Один шаг $t$:

$$
\eta \leftarrow \eta(t);\quad
(x, y) \sim \text{train};\quad
L = \ell(f_\theta(x), y);\quad
g = \nabla_\theta L;\quad
g \leftarrow \operatorname{clip}(g);\quad
\theta \leftarrow \operatorname{step}(\theta, g, \eta).
$$

Порядок, который нельзя нарушать: `zero_grad` **до** `backward` (иначе $g$ — сумма градиентов всех
прошлых шагов), `clip` **между** `backward` и `step`, lr — **до** `step`.

**Валидация** отвечает на вопрос, обобщает ли модель на данные, которых она не видела. Её считают:
- в режиме `model.eval()`: dropout выключен, нормализации берут накопленную статистику;
- под `torch.no_grad()`: граф не нужен, и экономится память;
- на всём валидационном наборе, чтобы число не зависело от случайного батча.

После этого модель возвращают в прежний режим.

## Формы тензоров

```shapes
X_train [N, D]
> get_batch: idx = randint(0, N, (B,), generator)
xb [B, D]
> model (train: dropout включён)
logits [B, K]
> cross_entropy
loss [] — backward → clip → step
## валидация раз в eval_every шагов
X_val [M, D]
> model.eval(), no_grad
val_loss [] — затем model.train()
axis K = число классов
```

## Задание

В `solution.py` (рабочая копия в `workspace/A09-training-loop/`):

1. `get_batch(X, y, batch_size, generator)`: ровно один вызов `torch.randint(0, N, (B,), generator=…)`.
2. `evaluate(model, loss_fn, X, y)` → `float` в режиме eval и без графа. Режим модели потом
   восстанавливается.
3. `train_loop(...)`: шаг в правильном порядке, история `{"train": [...], "val": [(step, loss), ...]}`.
   Валидация идёт после шагов, где `(step + 1) % eval_every == 0`, и после последнего.
4. `overfit_one_batch(...)`: тот же шаг, но всегда на одном батче.

Здесь можно пользоваться `torch.optim` и `nn.utils.clip_grad_norm_`: свои версии ты уже написал.

## Критерии готовности

- батч совпадает с `torch.randint` от генератора, пары $(x, y)$ не перепутаны;
- `evaluate` выключает dropout, не строит граф и возвращает модель в прежний режим;
- история лоссов `train_loop` совпадает с эталоном, валидация на шагах 39, 79, 119 (а при 50 шагах — 39 и 49);
- в момент `step()` lr равен `lr_fn(step)`, а норма градиента ≤ `max_grad_norm`;
- на спиралях валидационный лосс падает, точность на train > 80%;
- на одном батче лосс доходит до < 0.05 за 300 шагов.
