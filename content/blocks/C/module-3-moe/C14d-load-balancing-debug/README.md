# C14d. Отладка: bias-балансировка делает перекос только хуже

## Зачем это нужно

Механизмы с обратной связью (балансировка, адаптивные коэффициенты, контроллеры) ломаются
особенно наглядно: одна ошибка превращает отрицательную обратную связь в положительную, и система
не стабилизируется, а «разгоняется». В MoE это значит, что вместо выравнивания нагрузки часть
экспертов умирает, а обучение выглядит нормальным — loss по-прежнему падает.

## Что поменялось относительно C14

Архитектура та же — функции из C14. Код написан кем-то другим, и в нём **одна** ошибка.

## Формула

$$\mathcal{T} = \operatorname{top-}k(s + b),\qquad w = \operatorname{normalize}(s_\mathcal{T})$$

## Формы тензоров

```
scores [N,E] + bias [E] → indices [N,k]; load [E] → новый bias [E]
```

## Симптом

- aux loss считается правильно (баланс → 1, коллапс → E), и обучение по нему разгоняет роутер;
- `route_with_bias` выбирает экспертов по `scores + bias`, а веса берёт из `scores`;
- но если в цикле вызывать `update_bias` по текущей нагрузке, самый загруженный эксперт получает
  всё больше токенов, а самый слабый — всё меньше, пока не перестанет получать их совсем.
