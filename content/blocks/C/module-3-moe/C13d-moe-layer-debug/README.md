# Отладка: с top-1 всё верно, с top-2 токены теряют экспертов

## Зачем это нужно

Быстрая диспетчеризация MoE — это перестановки и обратная сборка по индексам, и тут легко
ошибиться так, что формы и даже большинство токенов окажутся правильными. Модель с такой ошибкой
обучается — просто хуже, и никто не замечает, что половина вычислений экспертов выбрасывается.

## Что поменялось относительно C13

Архитектура та же — `MoELayer` из C13. Код написан кем-то другим, и в нём **одна** ошибка.

## Формула

$$y_n = \sum_{j=1}^{k} w_{n,j}\,\text{FFN}_{e_{n,j}}(x_n)$$

## Формы тензоров

```shapes
h [N, C]
> разложить по слотам
слоты [N·k]
> сгруппировать по экспертам
> expert_e(h[tok_e]) · w
> собрать обратно
out [N, C]
> reshape
out [B, T, C]
```

Формы правильные, `forward_naive` правильный, роутер — эталон C12.

## Симптом

- `forward_naive` совпадает с оракулом;
- при `top_k = 1` `forward` совпадает с `forward_naive`;
- каждый эксперт получает ровно свои токены, всего $N \cdot k$ строк — значит, сортировка и
  группировка верны;
- но при `top_k ≥ 2` `forward` расходится с `forward_naive`, причём выход токена получается
  «слабее» — как будто от одного эксперта.
