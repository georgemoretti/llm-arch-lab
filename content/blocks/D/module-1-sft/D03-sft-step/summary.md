## TL;DR

Накопление градиентов в SFT: каждый микро-батч делает backward от **суммы** CE по меченым токенам, делённой на $N$ —
число токенов ответа во **всём** шаге (известно заранее по меткам). Тогда градиент == большому батчу. «Среднее
средних» (mean по микро-батчу / K) даёт токену из короткого микро-батча больший вес и совпадает с правильным только
при равных длинах. На нескольких GPU $N$ суммируют all-reduce. Шаг: lr по расписанию (A08) → zero_grad → накопление →
clip (норма до обрезки — в лог) → step.

## Формула

$$\mathcal L = \frac{1}{N}\sum_b \sum_{t\in S_b}\ell_t,\quad N = \sum_b |S_b|;\qquad \text{не}\ \frac1K\sum_b \frac{1}{|S_b|}\sum_{t\in S_b}\ell_t$$

## Формы тензоров

```
input_ids, targets [B, T] → logits [B, T, V] → сумма CE [] → / N → backward;  × K → clip → step
```

## Что поменялось относительно D02

Метки D02 идут в цикл обучения A09; нормировка лосса — на число токенов ответа во всём шаге, а не среднее по
микро-батчам.
