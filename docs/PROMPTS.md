# Промпты для Claude Code

Вручную эти промпты вставлять не нужно: команда `/next` (`.claude/commands/next.md`) сама
выбирает фазу по PROGRESS.md, берёт отсюда нужный промпт и выполняет его автономно.
Цикл пользователя: `/clear` → `/next` → посмотреть отчёт → `/next <правки, если есть>`.

---

## Промпт: Фаза 0 (стартовый, самый подробный)

```
Ты — senior ML-инженер и автор образовательных курсов. Мы строим «LLM Arch Lab» — локальный
интерактивный курс, где пользователь шаг за шагом реализует эволюцию LLM-архитектур от GPT-2
до современных гибридов, с автотестами, автоконспектами, визуализациями, задачами на отладку,
вопросами с собеседований и заданиями по статьям.

Сначала внимательно прочитай CLAUDE.md, docs/PLAN.md и docs/PROGRESS.md. Это источник
правды по архитектуре, формату задач и правилам контента.

Задача этой сессии — ТОЛЬКО Фаза 0 из PLAN.md:
1. Каркас репозитория по структуре из CLAUDE.md, pyproject.toml, .gitignore, LICENSE (MIT,
   если я не скажу иначе).
2. Пакет llmlab: загрузчик контента на pydantic с валидацией графа depends_on; CLI на typer
   (list, test, validate, init-workspace; serve пока заглушкой).
3. conftest.py с опцией --impl=workspace|reference|starter и фикстурой impl.
4. Раннер: pytest в subprocess с таймаутом 60 с, структурированный JSON-результат, запись
   каждой попытки в SQLite (.llmlab/progress.db): task_id, timestamp, passed/failed тесты,
   тексты ошибок, sha256 кода.
5. llmlab validate: для каждой задачи reference проходит все тесты, starter не проходит ни
   одного, у debug-задач багованная версия падает. Понятный отчёт через rich.
6. Демо-задача C00-causal-mha (causal multi-head self-attention, как в GPT-2) со ВСЕМИ
   файлами: task.yaml, README.md (теория своими словами, формула, схема форм тензоров
   [B,T,C]→[B,H,T,D], задание), starter.py, solution.py, test_task.py (формы; совпадение с
   эталоном; отсутствие утечки будущего — изменение токена t+1 не меняет выход в позиции ≤t;
   инвариантность к батчу), hints.md (3 подсказки по нарастающей), summary.md.
   Сообщения тестов должны объяснять ошибку, а не просто падать.
7. Готовая llmlab/core/gpt2.py — базовая модель GPT-2 (маленькая, читаемая, с комментариями),
   от которой будут считаться все «диффы» в блоке C.
8. docs/TASK_FORMAT.md — полная спецификация для авторов задач, включая шаблоны всех файлов
   и чек-лист качества задачи.
9. GitHub Actions: установка, pytest tests/, llmlab validate --all (только CPU).
10. Тесты самой платформы в tests/ (загрузчик, раннер, validate).

Ограничения:
- Не трогай фронтенд — это Фаза 1.
- Не пиши задачи C01+ — это Фаза 3.
- Тексты и комментарии в контенте на русском, код и идентификаторы на английском.
- Ничего не копируй из чужих статей: только свои формулировки и ссылки.

Ключевые интерфейсы (модели pydantic, сигнатура фикстуры impl, схема SQLite, формат
JSON-результата раннера) опиши в docs/TASK_FORMAT.md и кратко — в финальном отчёте.

В конце: прогони pytest tests/ и llmlab validate --all, обнови docs/PROGRESS.md (сделано,
решения, точный следующий шаг) и сделай коммит.
```

## Промпт: Фаза 1 (UI)

```
Прочитай CLAUDE.md, docs/PLAN.md, docs/PROGRESS.md. Делаем ТОЛЬКО Фазу 1 — локальный
веб-интерфейс.

Требования (подробно — в PLAN.md, Фаза 1):
- FastAPI-эндпоинты поверх уже существующих загрузчика и раннера (не дублируй логику).
- Фронтенд в web/: Vite + React + TS, Monaco, KaTeX, react-markdown. Сборка в llmlab/static/
  и коммит бандла. Всё офлайн, без CDN в рантайме.
- Экраны: карта курса (блоки → модули → задачи, статусы, зависимости), страница задачи
  (README | редактор, подсказки по одной, панель результатов тестов, Reset, Diff с эталоном
  после решения или 3 неудачных попыток), Ctrl+Enter = Run, автосохранение, тёмная/светлая тема.
- Отслеживание изменений файла workspace, отредактированного во внешнем IDE.
- Каркас визуализаций: реестр viz-компонентов и директива :::viz <id>::: в README.
- llmlab serve открывает браузер; сервер только на 127.0.0.1; защита от path traversal.

Дизайн: чистый, «инструментальный», без мусора; плотность информации как у хорошего IDE;
адаптивность до ширины ноутбука. В конце проверь
сквозной сценарий на C00 (открыть → написать → Run → зелёный), обнови PROGRESS.md, закоммить.
```

- llmlab notes build пересоздаёт конспект и сохраняет пользовательское поле.

## Промпт: фазы с контентом (3a, 3b, 4, 5a, 5b, 6a, 6b, A1–A4, B1–B4, D1–D4)

Один шаблон, меняется только номер фазы/подфазы:

```
Прочитай CLAUDE.md, docs/PLAN.md, docs/PROGRESS.md и docs/TASK_FORMAT.md.
Делаем ТОЛЬКО Фазу <N><подфаза> из PLAN.md: задачи <перечисли id>.

Для каждой задачи:
1. Сначала solution.py и test_task.py. Тесты проверяют формы, численное совпадение с эталоном
   и СВОЙСТВА механизма (например, для RoPE — сохранение нормы и зависимость score только от
   m−n; для KV-cache — равенство пошаговой и полной генерации; для MoE — каждый токен
   обработан ровно top-k экспертами, веса после перенормировки суммируются в 1).
   Сообщения об ошибках учат.
2. starter.py: та же сигнатура, тело — NotImplementedError и TODO-комментарии с намёком
   на шаги, без готового решения.
3. README.md: мотивация (какую проблему решает), «что поменялось относительно <diff_from>»,
   формула, схема форм тензоров, задание, критерии готовности. Своими словами.
   Гиперпараметры реальных моделей — только с указанием источника (config.json на HF или статья);
   если не уверен — пометь TODO-verify.
4. hints.md (3 уровня), summary.md (для конспекта).
5. Debug-задачи: файл buggy.py с ОДНИМ правдоподобным багом, тот же набор тестов;
   README описывает симптом, а не баг.
6. llmlab validate <id> — должен быть зелёным.

Для модуля также: paper-задания (3–5 вопросов на понимание + ссылка на статью и на разбор
Рашки — только ссылка), квиз (если база вопросов уже импортирована — бери оттуда по тегам;
иначе 8–10 своих вопросов в формате content/questions), и визуализации модуля из PLAN.md.

Работай задача за задачей. После каждой — validate и коммит. Если контекст подходит к
концу — остановись на границе задачи, обнови PROGRESS.md с точным списком оставшегося.
```
