# Отладка: FFN с весами Llama даёт не те числа

## Зачем это нужно

Ошибки в FFN коварны: любая «перестановка» внутри слоя оставляет формы правильными, модель
обучается с нуля почти так же хорошо, и баг всплывает только тогда, когда в код загружают
**чужие** обученные веса. Задача — научиться находить такие ошибки по свойствам формулы, а не
по формам тензоров.

## Что поменялось относительно C02

Архитектура та же — `silu`, `llama_ffn_hidden_dim`, `SwiGLUFFN` из C02. Код написан кем-то
другим, и в нём **одна** ошибка.

## Формула

$$
\operatorname{FFN}(x) = W_{\text{down}}\,\bigl(\operatorname{SiLU}(W_{\text{gate}}\,x) \odot W_{\text{up}}\,x\bigr)
$$

## Формы тензоров

```shapes
x [B, T, C]
> gate_proj, up_proj
g, u [B, T, F] — каждая
> ⊙
h [B, T, F]
> down_proj
y [B, T, C]
```

Формы в коде правильные.

## Симптом

- `silu` и `llama_ffn_hidden_dim` проходят свои тесты;
- модуль сохраняет форму, градиенты доходят до всех трёх матриц, на нулевом входе — ноль;
- с нуля такая модель обучается без проблем;
- но после загрузки весов `gate_proj` / `up_proj` / `down_proj` из Llama выход FFN расходится с
  `LlamaMLP` из `transformers` (max |Δ| порядка десятых), а если умножить веса `up_proj` на 3,
  выход меняется не в 3 раза.

Код — в `workspace/C02d-swiglu-debug/solution.py`. Найди и исправь ошибку.
