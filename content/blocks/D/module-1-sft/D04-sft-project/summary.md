## TL;DR

SFT учит модель формату диалога: отвечать в ходе ассистента, в нужной форме и останавливаться на `<|im_end|>`. Знания
и навыки приходят из предобучения. В проекте база, которая умеет задачи только в виде сплошного текста, за сотню шагов
SFT начинает отвечать в chat-формате, в том числе на примеры, которых в SFT не было. Та же модель без предобучения
выучивает формат, но не содержание (гипотеза LIMA в миниатюре). Лосс только по ответу на маленьких данных лучше лосса по
всем токенам. Оценка — по отложенным примерам, отдельно «верный формат» и «верный ответ»; JSON сравнивается как объект.

## Формула

$$\text{SFT: } \min_\theta \frac{1}{N}\sum_{t \in \text{ответ}} -\log p_\theta(x_{t+1}\mid x_{\le t}),\qquad \text{accuracy} = \frac{1}{|\text{test}|}\sum [\text{check}(\text{ответ модели})]$$

## Формы тензоров

```
пример → ids [T], targets [T] → collate [B, T] → sft_step;  вопрос → prompt ids → generate до <|im_end|> → ответ
```

## Что поменялось относительно D03

Шаг SFT стал экспериментом: данные по шаблону, генерация в chat-формате, проверка формата и ответа, сравнение базы с
моделью без предобучения и лосса по ответу с лоссом по всем токенам.
