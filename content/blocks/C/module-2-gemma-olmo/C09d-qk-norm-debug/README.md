# Отладка: после загрузки обученных весов QK-Norm даёт не тот выход

## Зачем это нужно

Самые неприятные ошибки — те, которые не видны на свежеинициализированной модели. Модуль
проходит юнит-тест «формы правильные, выход конечный», обучение даже идёт. Но стоит загрузить веса
реального чекпойнта — логиты не совпадают с эталонной реализацией. Здесь как раз такой случай:
нужно понять, почему расхождение появляется **только** при определённых значениях весов.

## Что поменялось относительно C09

Архитектура та же — `QKNormAttention` из C09. Код написан кем-то другим, и в нём **одна** ошибка.

## Формула

$$\hat q_h = w_q \odot \frac{q_h}{\operatorname{RMS}(q_h)},\qquad \text{score} = \frac{(R_i \hat q_h)\cdot(R_j \hat k_h)}{\sqrt{D}}$$

## Формы тензоров

```shapes
q_proj(x) [B, T, H·D]
> view + transpose
q [B, H, T, D]
> …
scores [B, H, T, T]
> …
out [B, T, C]
```

Формы правильные, causal-маска на месте, GQA правильный.

## Симптом

- режим `qk_norm="full"` (OLMo 2) совпадает с эталоном;
- режим `qk_norm="head"` (Gemma 3) совпадает с эталоном, **пока веса `q_norm` и `k_norm` единичные**
  (как сразу после инициализации);
- логиты ограничены, выход не зависит от масштаба `W_Q`, `W_K` — то есть нормы применяются;
- но с неединичными весами норм (как в обученной модели) режим `"head"` расходится с эталоном.
