## TL;DR

При генерации с KV-cache новые токены стоят на позициях S₀..S₀+T−1, где S₀ — длина кеша до
обновления. Если считать позиции RoPE как `arange(T)`, каждый шаг поворачивает q и k так, будто
токен в начале текста: первый кусок (prefill) верен, а дальше относительные расстояния до ключей
из кеша искажаются — генерация тихо расходится с полным прогоном.

## Формула

$$p_i = S_0 + i,\qquad \langle R_{p_i} q, R_{j} k\rangle = \langle q, R_{j - p_i} k\rangle \text{ — неверный } p_i \Rightarrow \text{неверное расстояние}$$

## Формы тензоров

```
start = cache.seq_len (до update) → positions = arange(start, start + T) [T] → cos, sin [T, D]
```

## Что поменялось относительно C05

Ничего в архитектуре: это C05, где позиции RoPE не сдвинуты на длину кеша. Урок — тестировать
кеш не только prefill-ом, а пошаговой генерацией и кусками, сравнивая с полным прогоном.
