# C14. Балансировка нагрузки экспертов: aux loss и bias DeepSeek-V3

## Зачем это нужно

Роутер MoE учится вместе с экспертами, и у этого обучения есть плохое устойчивое состояние —
**коллапс**: несколько экспертов чуть лучше остальных → роутер чаще отправляет к ним токены → они
учатся быстрее и становятся ещё лучше → остальные эксперты почти не получают токенов и градиента.
В итоге модель с 64 экспертами работает как модель с 3–4, а при распределённом обучении
перегруженные GPU тормозят все остальные.

Два подхода к борьбе с этим:

1. **Вспомогательный loss** (Shazeer et al. 2017, GShard, Switch Transformer): к основному loss
   добавляется $\alpha \cdot L_{\text{aux}}$, который минимален при равномерной нагрузке. Так делают
   Mixtral, OLMoE, Qwen3. Минус: этот градиент «спорит» с основным — роутеру приходится
   выбирать экспертов не только по качеству.
2. **Bias без градиента** (Wang et al. 2024, DeepSeek-V3): к оценке каждого эксперта добавляется
   bias, который используется **только для выбора** top-k. После каждого шага bias перегруженных
   экспертов немного уменьшается, недогруженных — увеличивается. Веса выходов берутся из исходных
   оценок, так что градиент основного loss не искажается. В config.json DeepSeek-V3 это
   `topk_method = "noaux_tc"`, а сам bias в HF — `e_score_correction_bias`. (Небольшой
   «последовательностный» aux loss в V3 всё же остаётся, но с очень маленьким коэффициентом.)

## Что поменялось относительно C13

| | C13 | C14 |
|---|---|---|
| обучение роутера | только через основной loss | + $\alpha L_{\text{aux}}$ (Mixtral: $\alpha = 0.02$, OLMoE: 0.01, Qwen3: 0.001) |
| или | — | bias для выбора экспертов, обновляемый правилом (DeepSeek-V3) |
| метрика | — | `expert_load`: доля назначений на каждого эксперта |

## Формула

Aux loss (Switch Transformer, обобщённый на top-k): по батчу из $N$ токенов

$$
f_i = \frac{1}{N k}\sum_{n=1}^{N} \mathbb{1}[i \in \operatorname{top-}k(p_n)],\qquad
P_i = \frac{1}{N}\sum_{n=1}^{N} p_{n,i},\qquad
L_{\text{aux}} = E \sum_{i=1}^{E} f_i\, P_i ,
$$

где $p_n = \operatorname{softmax}(\ell_n)$. $f_i$ и $P_i$ — распределения по экспертам (сумма 1).
При равномерной нагрузке $f_i = P_i = 1/E$ и $L_{\text{aux}} = 1$; при коллапсе в одного эксперта
$f = P = e_j$ и $L_{\text{aux}} = E$.

$f_i$ — счётчик, он не дифференцируем; градиент идёт только через $P_i$: эксперты с большой
нагрузкой $f_i$ получают сильный толчок вниз по вероятности. Нормировка: в HF Mixtral $f_i$
делится на $N$, а не на $Nk$, поэтому их значение в $k$ раз больше (минимум равен $k$) — на
обучение это влияет только через коэффициент $\alpha$.

Bias-балансировка (DeepSeek-V3), $s_{n,i}$ — sigmoid-оценки:

$$
\mathcal{T}_n = \operatorname{top-}k(s_n + b),\qquad w_{n,i} = \frac{s_{n,i}}{\sum_{j \in \mathcal{T}_n} s_{n,j}},\qquad
b_i \leftarrow b_i - \gamma \cdot \operatorname{sign}(\text{load}_i - \overline{\text{load}})
$$

## Формы тензоров

```
router_logits         [N, E]   (выход MoE-слоя из C13)
probs = softmax       [N, E]
indices = top-k       [N, k]
f = expert_load       [E]      (сумма 1, без градиента)
P = probs.mean(0)     [E]      (сумма 1, с градиентом)
L_aux                 []       скаляр

scores, bias          [N, E], [E]
route_with_bias       → weights [N, k] (из scores), indices [N, k] (по scores + bias)
update_bias(b, load)  → [E]
```

## Задание

В `solution.py` (рабочая копия в `workspace/C14-load-balancing/`) реализуй:

1. `expert_load(indices, n_experts)` → `[E]`;
2. `load_balancing_loss(router_logits, top_k)` → скаляр;
3. `route_with_bias(scores, bias, top_k, norm_topk_prob=True)` → `(weights, indices)`;
4. `update_bias(bias, load, gamma)` → новый bias.

## Критерии готовности

- баланс → 1, коллапс → ≈ E, совпадение с HF-формулой (делённой на $k$);
- градиент только через $P$; 30 шагов SGD по aux loss разгоняют «схлопнувшийся» роутер (макс. доля < 0.2);
- bias меняет выбор, но не веса; шаг ±γ по знаку перекоса;
- 300 шагов bias-балансировки выравнивают нагрузку (макс. < 0.18, мин. > 0.08 при идеале 0.125).
