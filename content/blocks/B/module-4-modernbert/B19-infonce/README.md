# Контрастивное обучение: InfoNCE с in-batch негативами, температура, recall@k

## Зачем это нужно

В B18 эмбеддинги брались из готовых моделей. Но MLM-предобучение (B09) учит предсказывать закрытые токены, а не
сближать тексты по смыслу. У голого BERT эмбеддинги «смотрят примерно в одну сторону» (анизотропия). Мы взяли восемь
фраз на разные темы: у `bert-base-uncased` средний косинус пар — 0.53 для mean pooling и 0.80 для `[CLS]`, а у
`all-MiniLM-L6-v2` после контрастивного обучения — 0.04. Когда все тексты похожи на все, искать по такому косинусу
трудно. Модели эмбеддингов (DPR, Sentence-BERT, E5, BGE) дообучают
**контрастивно**: на парах «запрос — подходящий документ».

Идея простая. Для каждого запроса в батче есть свой документ. Документы остальных пар — бесплатные **негативы** (in-batch
negatives): их не нужно размечать, они уже лежат в батче. Лосс — классификация «какой из $M$ документов батча мой» с
cross-entropy. Это **InfoNCE**: логарифм вероятности выбрать свой документ среди негативов. Чем больше батч, тем больше
негативов и тем труднее задача. E5 предобучали с батчем 32 768.

## Что поменялось относительно B18

| | B18 | B19 |
|---|---|---|
| что делаем с эмбеддингами | считаем готовыми, сравниваем косинусом | **учим**: сближаем пары, разводим остальные |
| матрица косинусов $[N, M]$ | результат поиска | **логиты** классификации: строка — запрос, столбец — документ |
| метрика | — | recall@k: доля запросов, у которых свой документ среди $k$ лучших |

## Формула

Пусть $\hat q_i, \hat d_j$ — L2-нормированные эмбеддинги, $d_i$ — позитив запроса $i$, а $d_{N}, \dots, d_{M-1}$ —
необязательные «трудные» негативы (hard negatives, например выдача BM25). Тогда

$$
\mathcal{L} = -\frac{1}{N}\sum_{i=0}^{N-1} \log
\frac{\exp(\hat q_i \cdot \hat d_i / \tau)}{\sum_{j=0}^{M-1} \exp(\hat q_i \cdot \hat d_j / \tau)}
= \operatorname{CE}\big(\hat Q \hat D^{\top} / \tau,\ [0, 1, \dots, N-1]\big).
$$

Градиент по запросу показывает, что происходит:

$$
\frac{\partial \mathcal{L}}{\partial \hat q_i} = \frac{1}{\tau N}\Big(\sum_j p_{ij}\, \hat d_j - \hat d_i\Big),
\qquad p_{ij} = \operatorname{softmax}_j(\hat q_i \cdot \hat d_j / \tau).
$$

Запрос тянется к своему документу и отталкивается от остальных, сильнее всего от тех, кого модель сейчас путает со
своим (большое $p_{ij}$).

**Температура.** Косинусы лежат в $[-1, 1]$. Без деления на $\tau$ softmax по ним почти равномерный: разница между
позитивом 0.9 и негативом 0.8 даёт отношение вероятностей $e^{0.1} \approx 1.1$. При $\tau = 0.05$ та же разница
становится $e^{2} \approx 7.4$. Малая $\tau$ сосредотачивает градиент на трудных негативах. В E5 $\tau = 0.01$, в
SimCSE 0.05, у CLIP она обучаемая. Если $\tau$ слишком мала, лосс начинает штрафовать и случайные «ложные» негативы
(в батче попался другой подходящий документ).

**Симметричный вариант** (CLIP, часто у пар без явного «запроса») добавляет второе направление: документ ищет свой
запрос среди запросов батча.

$$\mathcal{L}_{\text{sym}} = \tfrac{1}{2}\Big(\operatorname{CE}(S, y) + \operatorname{CE}(S^{\top}, y)\Big), \quad S = \hat Q\hat D^{\top}/\tau .$$

**recall@k** — доля запросов, у которых правильный документ среди $k$ документов с наибольшим score.

## Формы тензоров

```shapes
q [N, C]
d [M, C]
> q · dᵀ / τ
logits [N, M]
> CE по строкам с метками 0 … N − 1
loss []
## метрика
> topk по строке
topk [N, k]
recall []
axis N = запросов в батче
axis M = документов (N своих + hard negatives)
```

## Задание

В `solution.py` (рабочая копия в `workspace/B19-infonce/`) напиши:

1. `info_nce(q, d, temperature)` — in-batch негативы, `M ≥ N`, позитив запроса `i` — `d[i]`.
2. `symmetric_info_nce(q, d, temperature)` — среднее по строкам и столбцам (`M = N`).
3. `recall_at_k(scores, positives, k)` — float.

## Критерии готовности

- лосс = $-\frac1N\sum_i \log\operatorname{softmax}(q_i d^\top/\tau)_i$; температура делит; среднее, а не сумма; строки,
  а не столбцы;
- градиент по запросам = $(p - \text{onehot})\, d / (\tau N)$;
- одинаковые косинусы дают $\log M$, идеальные пары при малой $\tau$ дают 0;
- лишние документы `d[N:]` — негативы для всех запросов;
- симметричный вариант — среднее двух направлений;
- recall@k на ручном примере; $k > M$ не ломает `topk`;
- игрушечный bi-encoder за 60 шагов поднимает recall@1 с ~0.02 до ≥ 0.9.
