# T5: относительный позиционный bias — бакеты расстояний

## Зачем это нужно

В B02 позиция токена прибавлялась к его эмбеддингу один раз, на входе. Модель видела «я — токен 17», а не «этот
ключ на 3 левее меня», и отношение между позициями ей приходилось вычислять самой. Для языка важнее второе:
прилагательное перед существительным значит одно и то же в начале и в середине текста.

T5 (Raffel et al., 2019) убрала позиции из входа совсем. Вместо них в каждую голову attention добавляется
обучаемое число $b_h(j - i)$, которое зависит только от **сдвига** ключа относительно запроса. Близкие сдвиги
различаются точно, а дальние собираются в общие корзины (бакеты) логарифмической ширины: важно, на 1 или на 2 токена
сосед слева, но для 90 и 110 токенов разница уже несущественна. На бакетах держится и длинный контекст: модель,
обученная на 512 токенах, на любом расстоянии дальше 90 видит один и тот же «последний» бакет.

Идея относительных позиций — у Shaw et al. (2018). T5 упростила её до одного скаляра на бакет и голову. Похожий
приём используют ALiBi (штраф, линейный по расстоянию) и RoPE (C03).

## Что поменялось относительно B02

| | синусоиды (B02) | относительный bias T5 (B13) |
|---|---|---|
| где | прибавляются к эмбеддингу на входе | прибавляются к scores attention, $q \cdot k + b$ |
| от чего зависит | абсолютная позиция токена | только $j - i$: ключ минус запрос |
| обучение | фиксированная формула | таблица `[num_buckets, H]`, обучается |
| слои | один раз на входе | таблица только у слоя 0, его bias берут все слои стека |
| дальние позиции | у каждой свой вектор | одна корзина для всего дальше ≈ 0.7 · max_distance |

Числа t5-small — из [config.json](https://huggingface.co/google-t5/t5-small/blob/main/config.json):
`relative_attention_num_buckets = 32`, `num_heads = 8`. Параметра `relative_attention_max_distance` в этом файле нет,
действует значение по умолчанию `T5Config` — 128. Итого таблица 32 × 8 = 256 чисел на весь энкодер и ещё 256 на
декодер.

## Формула

Сдвиг $r = j - i$ (ключ минус запрос; $r < 0$ — ключ слева). **Двунаправленный** режим (энкодер): $N$ бакетов делятся
пополам, ключи справа ($r > 0$) идут во вторую половину. Внутри половины размера $N' = N/2$ расстояние $n = |r|$,
$e = N'/2$:

$$
\text{bucket}(n) =
\begin{cases}
n, & n < e \\
\min\Big(e + \Big\lfloor \dfrac{\ln(n / e)}{\ln(d_{\max} / e)}\,(N' - e) \Big\rfloor,\; N' - 1\Big), & n \ge e
\end{cases}
\qquad
\text{bucket}(r) = \tfrac{N}{2}\,[r > 0] + \text{bucket}(|r|).
$$

**Causal** режим (декодер): ключи справа всё равно закрыты маской, поэтому все $N$ бакетов отданы прошлому:
$n = \max(-r, 0)$, $N' = N$, $e = N/2$, у будущих ключей бакет 0.

Добавка к scores головы $h$: $\;s_{h,ij} = q_i \cdot k_j + B[\text{bucket}(j - i),\, h]$, где $B$ — `nn.Embedding(N, H)`.

Для $N = 32$, $d_{\max} = 128$ в двунаправленном режиме: сдвиги $0, -1, \dots, -7$ — бакеты $0 \dots 7$ (каждый свой);
$-8 \dots -11 \to 8$, $-12 \dots -15 \to 9$, $-16 \dots -22 \to 10$, …, $-91$ и дальше $\to 15$; справа то же со
сдвигом 16: $+1 \to 17$, $+8 \dots +11 \to 24$, $+91 \to 31$. Бакет 16 не используется никогда: сдвиг 0 попадает в
первую половину. Логарифм упирается в $N' - 1$ раньше, чем расстояние доходит до $d_{\max}$.

## Формы тензоров

```shapes
relative_position [T, S] — j − i, long
> relative_position_bucket
buckets [T, S] — 0 … N − 1
> bias = nn.Embedding(N, H)
values [T, S, H]
> permute(2, 0, 1), unsqueeze(0)
position_bias [1, H, T, S]
> + q·kᵀ [B, H, T, S]
scores [B, H, T, S]
axis N = num_buckets (32 у T5)
axis H = головы (8 у t5-small)
```

## Задание

В `solution.py` (рабочая копия в `workspace/B13-t5-relative-bias/`):

1. `relative_position_bucket(relative_position, bidirectional, num_buckets, max_distance)` — формула выше,
   поэлементно для тензора любой формы. Логарифмическая часть округляется **вниз**.
2. `relative_position_bias(bias, query_length, key_length, bidirectional, …, offset=0)` — матрица сдвигов
   «ключ минус запрос» `[T, S]`, бакеты, строки таблицы → `[1, H, T, S]`. `offset` — позиция первого запроса: при
   генерации с кешем запрос один (позиция $t$), а ключей $t + 1$.

## Критерии готовности

- бакеты совпадают с формулой T5 на сдвигах −300 … 300 в обоих режимах и с `transformers`
  (`T5Attention._relative_position_bucket`) при разных `num_buckets` / `max_distance`;
- бакет не убывает с расстоянием, первые $e$ расстояний различаются точно, всё дальнее — в последнем бакете половины;
  ключи справа — только во второй половине;
- bias имеет форму `[1, H, T, S]`, одинаков вдоль каждой диагонали ($j - i = \text{const}$) и различает «на 3 левее» и
  «на 3 правее»;
- causal: у последнего запроса все прошлые ключи получают разный bias, будущие — бакет 0; `offset` даёт ту же строку,
  что полный расчёт;
- совпадает с `T5Attention.compute_bias` для энкодера и декодера.
