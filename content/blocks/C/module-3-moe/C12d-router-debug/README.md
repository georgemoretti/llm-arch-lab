# Отладка: маршрут токена зависит от соседей по батчу

## Зачем это нужно

Роутер, который выдаёт «правдоподобные» веса (неотрицательные, сумма 1), не обязательно правильный.
Эта ошибка особенно коварна: обучение идёт, loss падает, но модель ведёт себя по-разному в
зависимости от того, с какими другими запросами её запустили в одном батче, а при генерации по
одному токену роутинг отличается от обучения. Такие баги находят тестом на **независимость** от
батча.

## Что поменялось относительно C12

Архитектура та же — `route` и `TopKRouter` из C12. Код написан кем-то другим, и в нём **одна** ошибка.

## Формула

$$s = \operatorname{softmax}(W_r x),\qquad w_e = \frac{s_e}{\sum_{j \in \operatorname{top-}k(s)} s_j}$$

## Формы тензоров

```shapes
x [B, T, C]
> reshape
x [N, C]
> W_r
logits [N, E]
> активация
scores [N, E]
> top-k
weights, indices [N, k]
```

## Симптом

- формы правильные, веса — float32;
- с перенормировкой веса каждого токена суммируются в 1;
- sigmoid-роутер DeepSeek-V3 работает правильно;
- но маршрут одного и того же токена меняется, если поменять **другие** токены в батче, а
  выбранные softmax-роутером эксперты — не всегда те, у которых наибольшие логиты.
