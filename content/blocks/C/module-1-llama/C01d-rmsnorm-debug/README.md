# C01d. Отладка: RMSNorm расходится с Llama на маленьких активациях

## Зачем это нужно

Портировать слой из чужой кодовой базы и получить «почти те же» числа — классическая ловушка.
Модель с такой нормализацией запускается, loss конечный, градиенты есть, а при загрузке
настоящих весов выход постепенно уезжает от оригинала. Найти такую ошибку можно, только если
понимать, **в каких условиях** две похожие формулы расходятся.

## Что поменялось относительно C01

Ничего нового в архитектуре: это тот же `rms_norm` / `RMSNorm`, что ты писал в C01, только код
написан кем-то другим, и в нём **одна** ошибка.

## Формула

Правильная формула (как в C01 и в Llama):

$$
\operatorname{RMSNorm}(x)_i = \frac{x_i}{\sqrt{\frac{1}{C}\sum_j x_j^2 + \varepsilon}}\;\gamma_i
$$

## Формы тензоров

```
x [B, T, C] → mean(x², dim=-1, keepdim) [B, T, 1] → делитель [B, T, 1] → x / делитель · weight → [B, T, C]
```

Формы в коде правильные — ошибка не в них.

## Симптом

Мы сравнили наш слой с `LlamaRMSNorm` из `transformers`:

- на обычных активациях (|x| ~ 1) выходы совпадают до 5-го знака, `assert_close` проходит;
- нулевой вход обрабатывается без NaN, fp16 не переполняется, градиенты в порядке;
- но на активациях масштаба 1e-3 (так бывает сразу после инициализации маленькими весами) выход
  отличается **в разы**, а с увеличенным eps расхождение видно и на обычном масштабе.

Код — в `workspace/C01d-rmsnorm-debug/solution.py`. Найди и исправь ошибку, не переписывая слой
целиком.
