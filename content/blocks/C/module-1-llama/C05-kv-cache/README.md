# C05. KV-cache — генерация без пересчёта прошлого

## Зачем это нужно

Авторегрессионная генерация выдаёт токены по одному: прогнали промпт → взяли следующий токен →
дописали его → прогнали снова. Если каждый раз прогонять всю последовательность заново, шаг $t$
стоит $O(t)$ проекций и $O(t^2)$ скалярных произведений, а вся генерация длины $N$ — $O(N^3)$
для attention.

Но causal-маска гарантирует: выход для позиции $t$ не зависит от токенов после $t$. Значит, при
добавлении нового токена **ключи и значения старых токенов не меняются** — их можно посчитать один
раз и сохранить. На каждом шаге новый токен считает только свои $q, k, v$, дописывает $k, v$ в
кеш и делает attention своего $q$ по всему кешу. Шаг становится $O(t)$, а повторных проекций нет.

Цена — память (это и считали в C04) и аккуратность: позиции, маска и порядок операций должны быть
такими, чтобы кеш давал **ровно** тот же результат, что полный прогон.

## Что поменялось относительно C04

| | C04 (GQA) | C05 (GQA + RoPE + KV-cache) |
|---|---|---|
| вход | вся последовательность `[B, T, C]` | только **новые** токены `[B, T, C]` + кеш прошлых |
| позиции | неявные: 0..T−1 (позиций ещё не было) | RoPE, позиции новых токенов `start..start+T−1`, `start = S_кеша` |
| ключи/значения | считаются для всех T | считаются для T новых, остальные берутся из кеша |
| маска | квадратная `[T, T]` | прямоугольная `[T, S]`, сдвинутая на `S − T` |
| что хранится | ничего | `k` (после RoPE) и `v`, `H_kv` голов, по каждому слою |

Типичные режимы работы одного и того же кода:

- **без кеша** (`cache=None`) — обучение и обычный прогон;
- **prefill** — весь промпт одним куском в пустой кеш;
- **decode** — по одному токену, `T = 1`;
- **chunked prefill** — длинный промпт кусками по несколько токенов поверх кеша.

## Формула

Пусть в кеше $S_0$ токенов и пришло $T$ новых, $S = S_0 + T$. Новый токен $i \in [0, T)$
стоит на абсолютной позиции $p_i = S_0 + i$:

$$
q_i = R_{p_i} W_Q x_i, \qquad k_i = R_{p_i} W_K x_i, \qquad v_i = W_V x_i
$$

$$
K \leftarrow [K_{\text{cache}};\, k_{0..T-1}], \quad V \leftarrow [V_{\text{cache}};\, v_{0..T-1}], \qquad
\text{out}_i = \operatorname{softmax}\!\left(\frac{q_i K^\top}{\sqrt{D}} + M_i\right) V
$$

$$
M_{i,j} = \begin{cases} 0, & j \le S_0 + i \\ -\infty, & j > S_0 + i \end{cases}
\qquad\text{— то есть } \texttt{tril}(\text{ones}(T, S),\ \text{diagonal} = S - T)
$$

Ключи кешируются **после** RoPE: позиция токена не меняется, поэтому поворачивать его ключ на
каждом шаге заново незачем.

## Формы тензоров

```
x (новые токены)       [B, T, C]
start = cache.seq_len  (S₀, до обновления!)
positions = arange(start, start + T)               [T]
cos, sin = rope_cos_sin(positions, D, θ)           [T, D]

q                      [B, H, T, D]     → apply_rope
k, v                   [B, H_kv, T, D]  → apply_rope (только k)
  │ cache.update(k, v): cat по оси времени (dim=2)
  ▼
K, V (весь кеш)        [B, H_kv, S, D]   S = S₀ + T
  │ repeat_kv
  ▼
K, V                   [B, H, S, D]
scores = q·Kᵀ/√D       [B, H, T, S]     + маска [T, S] со сдвигом S − T
out                    [B, H, T, D] → [B, T, H·D] → o_proj → [B, T, C]
```

Пример маски для $S_0 = 3$, $T = 2$ (строки — новые токены, столбцы — все ключи):

```
         k0 k1 k2 k3 k4
q (p=3)   1  1  1  1  0
q (p=4)   1  1  1  1  1
```

## Задание

В `solution.py` (рабочая копия в `workspace/C05-kv-cache/`) реализуй:

1. `KVCache.update(k, v)` — дописать `[B, H_kv, T, D]` к кешу и вернуть весь кеш;
   `seq_len` и конструктор даны;
2. `LlamaAttention.forward(x, cache=None)` — GQA из C04 + RoPE из C03 + кеш. Конструктор дан
   (имена как в HF, `rope_theta = 500 000` по умолчанию, как у Llama 3).

`rope_cos_sin`, `apply_rope`, `repeat_kv` импортируются готовыми из `llmlab.core.llama` (эталоны C03
и C04). `F.scaled_dot_product_attention` можно использовать, но осторожно: его `is_causal=True`
строит маску «от левого верхнего угла», и при `T < S` она неверна.

## Критерии готовности

- `KVCache.update` склеивает по оси времени в правильном порядке, кеши разных слоёв не делят состояние;
- без кеша — GQA + RoPE, совпадает с оракулом, будущее не протекает;
- prefill в пустой кеш даёт тот же выход; в кеше `[B, H_kv, T, D]` и ключи уже повёрнуты;
- по одному токену, prefill + decode и куски `4 + 3 + 5` — ровно то же, что полный прогон;
- `rope_theta` действительно используется.
