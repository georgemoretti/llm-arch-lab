# C01. RMSNorm (вместо LayerNorm)

## Зачем это нужно

Нормализация перед каждым подслоем держит активации в разумном масштабе: без неё
residual-поток от слоя к слою растёт или затухает, и глубокую сеть трудно обучить. GPT-2
использует **LayerNorm**: из вектора вычитается среднее, результат делится на стандартное
отклонение, затем применяются обучаемые масштаб γ и сдвиг β.

Авторы RMSNorm (Zhang & Sennrich, 2019) проверили гипотезу: а нужно ли центрирование? Их вывод —
основную пользу даёт именно **деление на масштаб** (инвариантность к тому, во сколько раз
«раздут» вектор), а вычитание среднего почти ничего не добавляет. Если его убрать, остаётся одна
статистика — среднеквадратичное значение (RMS), — и слой становится проще и немного быстрее:
одна редукция по C вместо двух, нет параметра β. Llama взяла RMSNorm, и с тех пор она стоит почти
во всех открытых LLM.

## Что поменялось относительно GPT-2

| | GPT-2: LayerNorm | Llama: RMSNorm |
|---|---|---|
| центрирование | вычитает среднее по C | **нет** |
| делитель | $\sqrt{\operatorname{Var}(x) + \varepsilon}$ | $\sqrt{\operatorname{mean}(x^2) + \varepsilon}$ |
| параметры | γ и β (по C каждый) | только γ (`weight`) |
| eps | 1e-5 | 1e-5 в Llama 3 (`rms_norm_eps` в config.json) |
| место в блоке | Pre-Norm: перед attention и MLP + финальная | то же самое |

Место нормализации **не меняется** — меняется только сам слой. Эксперименты с местом (Post-Norm,
sandwich) — в модуле 2 (C08).

## Формула

Для вектора $x \in \mathbb{R}^{C}$ (один токен):

$$
\operatorname{RMS}(x) = \sqrt{\frac{1}{C}\sum_{i=1}^{C} x_i^2 + \varepsilon},
\qquad
\operatorname{RMSNorm}(x)_i = \frac{x_i}{\operatorname{RMS}(x)} \cdot \gamma_i
$$

- $\varepsilon$ стоит **под корнем**: он защищает от деления на ноль и сглаживает поведение на
  почти нулевых векторах. Вариант «$+\varepsilon$ после корня» даёт другие числа именно там, где
  $\operatorname{mean}(x^2)$ сравнимо с $\varepsilon$, — несовместимо с весами Llama.
- Свойство: $\operatorname{RMSNorm}(c\,x) = \operatorname{RMSNorm}(x)$ для любого $c > 0$ (если
  $\varepsilon$ мал по сравнению с $\operatorname{mean}(x^2)$). А вот сдвиг $x + b$ результат
  меняет — в отличие от LayerNorm.
- При $\gamma = 1$ у выхода $\operatorname{RMS} \approx 1$, т.е. $\lVert y \rVert \approx \sqrt{C}$.

**Точность.** В Llama нормировка считается в float32, даже если модель в bf16/fp16: вход
приводится к float32, нормируется, возвращается в исходный dtype и только потом умножается на γ.
Причина простая: в fp16 максимум ≈ 65 504, и $x^2$ переполняется уже при $|x| > 256$.

## Формы тензоров

```
x                    [B, T, C]
  │ .float()            — считаем в fp32
  │ pow(2).mean(dim=-1, keepdim=True)
  ▼
mean_sq              [B, T, 1]     одно число на токен
  │ + eps, rsqrt
  ▼
inv_rms              [B, T, 1]
  │ x * inv_rms          — трансляция [B,T,1] → [B,T,C]
  │ .to(x.dtype)
  │ * weight             — weight [C] транслируется по B и T
  ▼
y                    [B, T, C]
```

Каждый токен нормируется **независимо**: статистика берётся только по оси C.

## Задание

В `solution.py` (рабочая копия в `workspace/C01-rmsnorm/`) реализуй:

1. `rms_norm(x, weight, eps)` — вход `[..., C]` (любое число ведущих осей), выход той же формы и
   того же dtype.
2. `RMSNorm.forward(x)` — конструктор уже готов (параметр `weight`), не меняй его.

Ограничения: нельзя использовать `F.rms_norm` и `nn.RMSNorm` (тесты это проверяют).

## Критерии готовности

- форма и dtype выхода совпадают со входом;
- выход совпадает с формулой (`atol=1e-5`), в том числе на маленьких активациях (|x| ~ 1e-3),
  где важно, что eps стоит под корнем, и с нестандартным eps;
- при γ = 1 RMS каждого токена ≈ 1; умножение входа на константу не меняет выход;
- вход со сдвигом не центрируется (это не LayerNorm);
- нулевой вход даёт нули без NaN;
- fp16-вход с |x| ~ 300 не переполняется;
- у модуля единственный параметр `weight`; токены и примеры батча не влияют друг на друга;
  градиент доходит до `weight` и до входа.
