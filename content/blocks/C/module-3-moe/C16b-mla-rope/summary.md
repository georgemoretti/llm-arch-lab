## TL;DR

RoPE несовместим с поглощением весов MLA: поворот, зависящий от позиции ключа, встаёт между $W_{UK}$
и латентом. DeepSeek разделяет голову на две части: $d_n$ измерений без позиций из латента
(поглощаются) и $d_r$ измерений с RoPE, где ключ $k^{\text{rope}}$ один на все головы (как в MQA). Кеш —
латент $c$ и повёрнутый $k^{\text{rope}}$: у DeepSeek-V3 $512 + 64 = 576$ чисел на токен и слой, ≈ 69 КиБ на
токен для всей модели в bf16 — в ~71 раз меньше MHA с теми же 128 головами.

## Формула

$$\text{score} = \frac{q^{\text{nope}\top} W_{UK} c + (R_i q^{\text{rope}})^\top (R_j k^{\text{rope}})}{\sqrt{d_n + d_r}},\qquad
\text{кеш} = L\,(r + d_r)\,S$$

## Формы тензоров

```
q [B,H,T,dn+dr];  kv_a_proj_with_mqa(x) → c [B,T,r], k_rope [B,T,dr];  кеш: [B,S,r], [B,S,dr]
k = cat(k_nope [B,H,S,dn], k_rope → [B,H,S,dr])
```

## Что поменялось относительно C16

У головы появилась RoPE-часть с общим на все головы ключом; кеш хранит латент и этот ключ; масштаб —
$1/\sqrt{d_n + d_r}$. Часть без позиций по-прежнему поглощается.
