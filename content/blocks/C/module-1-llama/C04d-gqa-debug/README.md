# C04d. Отладка: GQA работает как MHA и как MQA, но не с группами

## Зачем это нужно

Ошибки в GQA коварны: модель не падает, формы правильные, и если тестировать только крайние
случаи (MHA или MQA), всё сходится. А при загрузке настоящих весов Llama 3 (32 головы, 8 KV-голов)
модель выдаёт мусор, потому что головы получили «не те» K и V. Задача — найти такую ошибку,
сравнивая поведение при разных $(H, H_{kv})$.

## Что поменялось относительно C04

Архитектура та же — `repeat_kv`, `kv_cache_bytes` и `GroupedQueryAttention` из C04. Код написан
кем-то другим, и в нём **одна** ошибка.

## Формула

$$
\text{head}_h = \operatorname{softmax}\!\left(\frac{Q_h K_{\lfloor h/r \rfloor}^\top}{\sqrt{D}} + M\right) V_{\lfloor h/r \rfloor},
\qquad r = H / H_{kv}
$$

## Формы тензоров

```
q [B,H,T,D];  k, v [B,H_kv,T,D] → repeat_kv → [B,H,T,D] → attention → [B,T,H·D] → o_proj
```

Все формы в коде правильные.

## Симптом

- все формы верные, causal-маска на месте, `kv_cache_bytes` считает правильно;
- при $H_{kv} = H$ (MHA) и при $H_{kv} = 1$ (MQA) выход совпадает с эталоном;
- при $1 < H_{kv} < H$ выход **другой**, и GQA перестаёт совпадать с MHA, у которого веса K/V
  внутри каждой группы скопированы.

Код — в `workspace/C04d-gqa-debug/solution.py`. Найди и исправь ошибку.
