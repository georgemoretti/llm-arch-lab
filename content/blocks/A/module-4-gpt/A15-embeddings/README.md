# Эмбеддинги токенов и позиций, weight tying

## Зачем это нужно

В A10 модель видела окно из 4 символов и склеивала их эмбеддинги в один вектор. Порядок символов при
этом задавался самой склейкой: первые 16 чисел — первый символ, следующие 16 — второй. В трансформере
склейки нет. Каждая позиция последовательности обрабатывается одними и теми же весами, а attention
(A16) смешивает позиции взвешенной суммой, которой порядок слагаемых безразличен. Без дополнительной
информации модель не отличит «кот съел мышь» от «мышь съела кот».

Поэтому к вектору токена прибавляют **вектор позиции**. В GPT-2 это просто вторая обучаемая таблица:
у позиции 0 свой вектор, у позиции 1 свой, и так до `block_size − 1`. Модель сама выучивает, что делать
с этими векторами.

Вторая идея задачи — **weight tying**. Входная таблица эмбеддингов имеет форму $[V, C]$, а выходной слой
переводит вектор $C$ в логиты по словарю, и его вес тоже $[V, C]$. GPT-2 использует для обоих один и тот
же тензор. Параметров меньше на $V \cdot C$: у GPT-2 small это 38.6 млн из 124 млн. А токен, похожий на
выход модели, — это токен с похожим эмбеддингом, что естественно.

## Что поменялось относительно A10

| | A10 | A15 |
|---|---|---|
| вход | окно из $k$ символов | вся последовательность $[B, T]$ |
| порядок | склейка эмбеддингов окна | вектор позиции прибавляется к вектору токена |
| предсказаний за проход | одно (следующий символ после окна) | $T$: для каждой позиции |
| выходной слой | свой `nn.Linear` | связан с эмбеддингами (weight tying) |

Модель в этой задаче (`EmbeddingLM`) пока не смешивает позиции. Логиты позиции $t$ зависят только от
токена $t$ и номера $t$, то есть это биграммная модель. Attention добавим в A16.

## Формула

$$
h_t = E_{x_t} + P_t,\qquad \text{logits}_t = h_t\, E^{\top} \in \mathbb{R}^{V},
\qquad E \in \mathbb{R}^{V \times C},\ P \in \mathbb{R}^{\text{block\_size} \times C},
$$

$$
\mathcal{L} = \frac{1}{B T} \sum_{b, t} -\log \operatorname{softmax}(\text{logits}_{b,t})_{y_{b,t}}.
$$

При связанных весах градиент по $E$ складывается из двух вкладов: от входа (строки $E_{x_t}$) и от выхода
(вся матрица через $E^{\top}$). Autograd сложит их сам, если это действительно один тензор.

Перед обучением полезно проверить стартовый loss. При весах $\mathcal{N}(0, 0.02^2)$ логиты почти нулевые,
распределение почти равномерное, и $\mathcal{L} \approx \ln V$ ($\ln 67 \approx 4.20$ для нашего корпуса).

## Формы тензоров

```shapes
idx [B, T] — номера токенов
> wte: nn.Embedding(V, C)
tok [B, T, C]
- pos = arange(T) → wpe: nn.Embedding(block_size, C) → [T, C]
> tok + pos (broadcast по батчу)
h [B, T, C]
> lm_head: h @ wteᵀ (тот же вес [V, C])
logits [B, T, V]
> flatten → cross_entropy с targets [B·T]
loss [] — среднее по B·T позициям
axis C = n_embd
axis V = размер словаря
```

## Задание

В `solution.py` (рабочая копия в `workspace/A15-embeddings/`):

1. `TokenPositionEmbedding.forward(idx)` — сумма эмбеддингов токенов и позиций $0 \dots T-1$.
   `T > block_size` → `ValueError`.
2. `tie_weights(lm_head, wte)` — связать веса так, чтобы это был один параметр.
3. `count_params(model)` — число обучаемых чисел, связанный вес считается один раз.
4. `EmbeddingLM.forward(idx, targets=None)` → `(logits, loss)`; без `targets` loss = `None`.

Конструкторы готовы: имена `wte`, `wpe`, `lm_head` — как в `llmlab/core/gpt2.py`.

## Критерии готовности

- выход `TokenPositionEmbedding` = `wte(idx) + wpe(0 … T − 1)`, позиции с нуля и общие для батча;
- одинаковый токен на разных позициях даёт разные векторы; `T = block_size` можно, больше — `ValueError`;
- `lm_head.weight` и `wte.weight` — один объект, и его градиент — сумма вкладов входа и выхода;
- `count_params` не считает связанный вес дважды;
- логиты и loss совпадают с эталоном, стартовый loss ≈ $\ln V$;
- за 300 шагов на корпусе loss падает больше чем на 1 ниже $\ln V$.
