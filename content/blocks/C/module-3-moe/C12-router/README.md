# Роутер MoE: оценки → top-k → перенормировка

## Зачем это нужно

В dense-модели (Llama, C06) каждый токен проходит через один и тот же FFN, и FFN — это ~2/3
параметров блока. Хочется больше параметров (больше «памяти» модели), но не больше вычислений на
токен. Mixture-of-Experts (MoE) делает так: вместо одного FFN — $E$ независимых FFN-«экспертов», и
каждый токен обрабатывают только $k \ll E$ из них. Параметров в $E$ раз больше, а FLOPs на токен —
как у $k$ экспертов.

Кто решает, каким экспертам достанется токен? **Роутер** — маленький линейный слой, который по
скрытому состоянию токена выдаёт оценку каждому эксперту. Дальше выбираются $k$ лучших, а их
выходы складываются с весами. Роутер — самая «хрупкая» часть MoE: от него зависят и качество, и
балансировка нагрузки (C14), и он обучается только через веса выбранных экспертов.

Эта задача — только роутер; сам MoE-слой — в C13.

## Что поменялось относительно C02

| | C02 (SwiGLU FFN) | MoE (C12–C13) |
|---|---|---|
| FFN на токен | один общий | $k$ из $E$ экспертов, свои для каждого токена |
| новые параметры | — | роутер $W_r \in \mathbb{R}^{E \times C}$ (без bias) |
| выход | $\text{FFN}(x)$ | $\sum_{e \in \text{top-}k(x)} w_e(x)\, \text{FFN}_e(x)$ |

Варианты роутера в реальных моделях (все числа — config.json на Hugging Face):

| модель | экспертов | $k$ | оценки | перенормировка | множитель |
|---|---|---|---|---|---|
| Mixtral 8x7B | 8 | 2 | softmax | да | 1 |
| OLMoE-1B-7B | 64 | 8 | softmax | нет (`norm_topk_prob = false`) | 1 |
| Qwen3-30B-A3B | 128 | 8 | softmax | да | 1 |
| DeepSeek-V3 | 256 | 8 | **sigmoid** | да | 2.5 (`routed_scaling_factor`) |

DeepSeek-V3 вдобавок выбирает экспертов в два этапа (сначала 4 группы из 8, потом 8 экспертов
внутри них — `n_group`, `topk_group`) и добавляет к оценкам bias для балансировки (C14). Групповой
выбор в задаче не реализуем: он нужен для распределения экспертов по устройствам.

## Формула

Для токена $x \in \mathbb{R}^C$:

$$
\ell = W_r x \in \mathbb{R}^E,\qquad
s = \begin{cases}\operatorname{softmax}(\ell) & \text{(Mixtral, Qwen)}\\ \sigma(\ell) & \text{(DeepSeek-V3)}\end{cases}
$$

$$
\mathcal{T} = \operatorname{top-}k(s),\qquad
w_e = \alpha \cdot \frac{s_e}{\sum_{j \in \mathcal{T}} s_j}\ \ (e \in \mathcal{T}),\qquad
\alpha = \texttt{routed\_scaling\_factor}
$$

Без перенормировки $w_e = \alpha\, s_e$. Softmax берётся **по экспертам** — у каждого токена своё
распределение.

Полезное тождество: для softmax перенормированные веса top-k равны softmax только по $k$
выбранным логитам — общий знаменатель сокращается:

$$
\frac{e^{\ell_e}/Z}{\sum_{j \in \mathcal{T}} e^{\ell_j}/Z} = \operatorname{softmax}(\ell_\mathcal{T})_e .
$$

Поэтому в исходном коде Mixtral сначала брали top-k логитов, а потом softmax — это то же самое.

Градиент: индексы top-k не дифференцируемы, роутер учится **только через веса** $w_e$. При $k = 1$
с перенормировкой вес всегда равен 1 и градиента нет — поэтому Switch Transformer (top-1) умножает
выход эксперта на ненормированную вероятность $s_e$.

## Формы тензоров

```shapes
x [B, T, C]
> reshape — каждый токен роутится отдельно
x [N, C]
> x · W_rᵀ, в float32
logits [N, E]
> softmax по оси E (или sigmoid)
scores [N, E]
> top-k по оси E
weights, indices [N, k] — weights в float32
```

## Задание

В `solution.py` (рабочая копия в `workspace/C12-router/`) реализуй:

1. `route(logits, top_k, scoring_func="softmax", norm_topk_prob=True, routed_scaling_factor=1.0)`
   → `(weights [N, k] float32, indices [N, k])`;
2. `TopKRouter.forward(x)` → `(logits [N, E], weights, indices)`: склеить токены, логиты в float32,
   `route`. Конструктор дан (`weight [E, C]`, как `gate.weight` в HF).

## Критерии готовности

- top-k по оценкам; с перенормировкой сумма весов = 1, без неё — исходные вероятности;
- DeepSeek-V3: sigmoid, top-8 из 256, сумма весов 2.5;
- маршрут токена не зависит от других токенов батча;
- перенормированный top-k softmax = softmax по выбранным логитам;
- логиты в float32 даже при bf16-входе; при top-1 без перенормировки градиент доходит до роутера,
  с перенормировкой — нет.
