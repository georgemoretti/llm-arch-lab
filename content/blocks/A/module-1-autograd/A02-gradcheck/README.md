# Проверка градиентов конечными разностями

## Зачем это нужно

Autograd из A01 выдаёт числа, но как убедиться, что они верны? Ошибка в одной локальной
производной не ломает обучение заметно: лосс всё равно падает, только хуже. Такую ошибку можно
искать неделями. Поэтому любой новый backward (свой autograd, ручной backprop в A04–A05,
собственная операция в PyTorch) сначала сверяют с **численной производной**. Её можно посчитать для
любой функции, которую умеешь вычислять, не зная формулы производной.

Проверка медленная: на каждый вход нужно два вызова функции. Поэтому её делают на маленьких размерах
и только при отладке. В PyTorch для этого есть `torch.autograd.gradcheck`, и здесь ты напишешь его
упрощённый вариант.

## Что поменялось относительно A01

| | A01: autograd | A02: численная проверка |
|---|---|---|
| откуда производная | локальные производные + chain rule | только значения функции |
| стоимость | один обратный проход | 2 вызова f на каждый вход |
| точность | точная (до округления) | приближённая, зависит от h |
| зачем | считать градиенты при обучении | проверять, что autograd считает верно |

## Формула

Односторонняя разность $\frac{f(x+h) - f(x)}{h}$ ошибается на $\tfrac{h}{2} f''(x)$. Это видно
из ряда Тейлора. **Центральная** разность сокращает член второго порядка:

$$
\frac{\partial f}{\partial x_i} \approx \frac{f(x + h\,e_i) - f(x - h\,e_i)}{2h},
\qquad \text{ошибка формулы} \approx \frac{h^2}{6}\,f'''(x).
$$

Здесь $e_i$ — единичный вектор по $i$-й координате. Уменьшать $h$ бесконечно нельзя: $f(x+h)$ и
$f(x-h)$ становятся почти равны, и при вычитании пропадают значащие цифры. Ошибка округления растёт
как $\varepsilon_{\text{маш}}\,|f| / h$. Сумма двух ошибок минимальна примерно при
$h \approx \varepsilon_{\text{маш}}^{1/3}$, а в float64 ($\varepsilon \approx 2\cdot10^{-16}$) это
$h \sim 10^{-5}$. Поэтому проверку всегда делают в float64: во float32 даже лучшая точность — около
$10^{-3}$.

Сравнивать градиенты нужно **относительной** ошибкой. Абсолютная ошибка $10^{-6}$ — это отлично
для градиента $\sim 1$ и катастрофа для градиента $\sim 10^{-7}$:

$$
\operatorname{rel}(a, b) = \max_i \frac{|a_i - b_i|}{\max(|a_i|,\ |b_i|,\ \varepsilon)}.
$$

$\varepsilon$ в знаменателе нужен, чтобы два нуля давали ошибку 0, а не NaN.

## Формы тензоров

```shapes
x [N] — точка (любая форма, float64)
> для каждого i: x ± h·e_i
f(x + h·e_i), f(x − h·e_i) [] — два вызова f на элемент
> (f₊ − f₋) / 2h
grad [N] — та же форма, что у x
> rel_error с градиентом из backward
err [] — меньше tol → проверка пройдена
```

## Задание

В `solution.py` (рабочая копия в `workspace/A02-gradcheck/`) реализуй:

1. `numerical_grad(f, x, h=1e-5)` — центральные разности для каждого элемента `x` любой формы.
   `f` получает тензор и возвращает число. Исходный `x` менять нельзя.
2. `rel_error(a, b, eps=1e-12)` — максимум по элементам формулы выше, возвращает `float`.
3. `check_value_grads(fn, xs, h=1e-6, tol=1e-6)` — для функции `fn(*values) -> Value` (на готовом
   `Value` из `llmlab.core.autograd`) сравни градиенты `backward()` с `numerical_grad`. Верни пару
   `(err < tol, err)`.

`torch.autograd` не нужен: часть функций в тестах написана на чистом Python, и для них autograd
вообще не работает.

## Критерии готовности

- градиент той же формы, что `x`; на $f = \sum x^3$ он равен $3x^2$ с точностью $10^{-8}$;
- после вызова `x` не изменился;
- при $h = 10^{-3}$ ошибка порядка $h^2$, а не $h$, то есть разность центральная;
- `h` по умолчанию даёт точность лучше $10^{-8}$;
- функции на чистом Python (через `.tolist()`) и функции от матрицы считаются верно;
- `rel_error`: два нуля дают 0, ошибка относительная, учитывает знак, берётся максимум по
  элементам;
- `check_value_grads` подтверждает верный autograd и ловит операцию с неверной локальной
  производной.

Запуск: `llmlab test A02-gradcheck`.
